# 保存和继续修改 HTML 作品

图解、交互演示和单文件小工具，可以保留为同一件作品，继续修改并回看旧版。

## 保存一份图解

受托制作的自包含 HTML 图解、原型，或准备反复使用、持续改版的小工具，猫应主动保存为作品并发固定版本卡，不需要每次额外提醒“存成作品”。也可以直接说：“把这份 HTML 图解保存成可续改的作品。”

保存后的内容会出现在原对话的作品目录中，卡片仍发回原 Chat。聊天卡片指向发出时的那个版本；后续改版不会改写原卡片。

随聊天解释局部的小图或控件可以直接用 HTML 富块，也会留在聊天历史中并有目录预览。作品额外提供稳定身份与版本链。按用途选择，篇幅只作提示；一个很小但会反复用的计算器也适合存为作品。

## 接着改，并保留原版

对猫说：“在这件作品上继续改一版，保留原版。”猫先读取原版，再沿同一件作品提交下一版，不按标题另建一件同名作品。

起初是聊天 HTML、后来开始围绕同一成果持续迭代时，猫在现有权限内先找回原 HTML 和来源消息，把原内容作为作品首版保全，再提交修改版；不会凭重写稿捏造旧版。一次修字不必机械升级，已有作品的小修仍沿原作品。

点作品卡片，在页面顶部的“作品版本”中选择旧版或新版。“刷新版本”只检查有没有更新，保留你当前看的版本和交互状态；选择另一个版本才会切换。

点“返回”回到原来的对话或作品列表。原对话里的未发送草稿应保持不变。

## 内容和容量

每版支持最多 1 MiB 的单文件 HTML，每件最多保存 256 版。达到上限会明确拒绝下一版，已保存的历史不被淘汰。正文不会因为过长被静默截断。

页面沿现有 HTML 沙盒展示，允许自身脚本交互，不能读取主页面和登录信息。它不等于任意完整网站或多文件应用；外部资源是否可用取决于原来的链接和权限。自行绑定脚本事件，避免依赖内联 onclick 属性。

## 给猫的操作约定

使用现有 `cat_cafe_work`：`create` 的 source 为 `{kind: "html", html: "完整源码"}`，`submit` 带原 `contentRef`、当前 `expectedOwnerRevision` 和完整新源码；保存成功后才用 `publish-reference` 附卡。

`read-body` 读取指定 `{contentRef, ownerRevision}` 的原始源码。若返回分页，保持 command 和 snapshot 不变，按 nextCursor 拼齐所有 json 后解析。保存和附卡是两件事：附卡未确认时重试同一个引用，不重新提交一个版本。未经当前授权，不续改别人的作品。
