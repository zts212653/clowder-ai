## 第一幕 · 能不能把记忆交给别人

2026-02 → 03：接一个现成的记忆服务，一个月后拆掉，自己造

### 1. 一只猫一个库，还是全家一个库（2026-02-08）

- **从** 共享库之外，每只猫再有个人库 **→ 到** 全家只用一个共享库　⑥治理 ◆方法
- **痛点**：接入本机部署的第三方记忆服务 Hindsight，先要定怎么分库。Ragdoll推荐共享知识放共享库，个人经验放各猫自己的库。
- **代价**：「既然不做个人 bank，那么"避免混在一起"的能力必须由 tags/metadata 约定来承担」（ADR5 L64）。
- **谁推了一把**：operator否了：「如果缅因大猫不知道你为什么如此架构他要如何 review 你的代码呢？」（ADR5 L49）
- **留下的**：「架构决策必须共享，否则其他猫无法理解 why」（ADR5 L52）

### 2. 记忆能不能外包（2026-03-11 → 03-17）

- **从** 本机跑的第三方记忆服务 **→ 到** 自建检索与治理链，真相留在家里　①证据 ⑥治理
- **痛点**：「Hindsight（外部记忆服务）已停用——operator觉得实在难用。」（F102 L31） 3/11 的咨询记下三个痛点：本机端口常连不上；写进去的东西碎片化；问"谁给我取名"，返回一堆含"名字"的无关内容（STORY L39；原咨询未导出，You 家已核实）。
- **选了**：「本地优先，不上外部服务/图数据库」（F102 L1254）。猫不能直接往长期库里写：「retain 不能直写长期库（碎片化垃圾入库教训）」（F102 L35）。动手前先建评测集，因为「上次痛点是"找不对"不是"存不了"」（F102 L1270）。
- **代价**：拆掉用了五千行代码的旧链路（「-5000 行」（ADR20 L28））；从此检索、索引都得自己养。
- **谁推了一把**：同一次外部咨询指出三处要改，其中一条：「accepted ≠ truth，materialized 才是终态」（F102 L1265）
- **留下的**：这是 8 月回看时的判断，不是 3 月现场的结论：外部库可以当外挂，"什么算真的、谁说了算、错了怎么撤"外包不出去（8 月旧稿 L114–116）。5 月的深读也承认 Hindsight 的工程在进步，检索和集成值得借鉴。

## 第二幕 · 先把"找"做对

2026-03 → 06：搜还是灌、摘要还是原文、给什么打分、建了为什么没人用

### 3. 搜，还是灌（2026-03-05）

- **从** 把旧上下文整段灌给新会话 **→ 到** 新会话需要时自己去搜　③读取
- **痛点**：会话一封存，新会话几乎失忆。让旧会话临走前写个总结？
- **选了**：「恢复哲学是"搜"不是"灌"」（F065 L89）
- **代价**：新会话得自己多搜几次才能接上。也不是一律不推：「Task 快照直接注入 bootstrap（例外于 KD-1）」（F065 L90）。
- **谁推了一把**：operator：「不是让快没 context 的旧猫写总结——那时候他已经记不清了。」（F065 L29）
- **留下的**："拉"而不是"推"，这是后来纲领的种子。

### 4. 向量怎么加进来（2026-03-12 → 03-21）

- **从** 关键词先召回，向量只负责重排 **→ 到** 两路各自召回，再融合　③读取
- **痛点**：第一版向量跑在 CPU 上，operator：「你用 cpu！为什么不用 gpu 啊！！你这实现我拒绝。」（LL L642） 实测又发现：「rerank 只重排已召回的，不发现新文档」（F102 L799–800）。
- **选了**：关键词和向量各自召回，用 RRF 融合；向量挂了就退回关键词：「增强层不能拖累基础能力」（F102 L1273）。
- **代价**：都是当时的版本和配置：「GPU Embedding server 增加一个 Python 进程（~900MB 内存）」（ADR20 L194）；开源版默认不开：「我们自己 = 全部 on。开源仓 = 全部 off」（F102 L1448）。

### 5. 存摘要，还是存原文（2026-03-18 → 05-23）

- **从** 用摘要代替原文 **→ 到** 原文永远在，摘要只指路　①证据 ✦横切
- **痛点**：一查，「340 thread 中 326 个 summary 为空」（F102 L1286）。
- **为什么**：「模型会一本正经地拿摘要当真相源回答。」（F209 L19）
- **选了**：「压缩不等于丢弃，摘要必须可穿透」（F102 L502）；「压缩 = 生成更好的索引层摘要，不是删除原件。」（F163 L154） 不建一份"编译好的百科"，因为「persistent Compiled Wiki would create a second truth surface」（F169 L277）。
- **代价**："摘要记忆"这个需求被明确推后：「摘要记忆是必须解决的问题，但不属于 F209。」（F209 L224）
- **谁推了一把**：「两份云端调研 + 三只本地猫全票：替代式压缩丢失触发锚点」（F163 L336）

### 6. 给什么打分（2026-04-19 → 05-14）

- **从** 一个"置信度"说了算 **→ 到** 只给"好不好找"打分，不给"真不真"打分　③读取 ✦横切
- **痛点**：搜索结果上的置信度在撒谎：最对的那条标 low，半相关的标 high（F163 L238）。
- **当时的选项**：学别家让模型给自己打分？当时拆了 MemOS 的源码，发现「模型自评集中在 0.6-0.85 成功区间，负样本几乎没有」（F200 L38）。
- **选了**：「confidence = f(rank)，authority 作为独立字段暴露。」（F163 L240） 再往后：「不给 truth/authority 打分，只给 navigation utility 打分。」（F200 L40）
- **代价**：「consumption ≠ correctness」（F200 L492）。7 月又识别出消费正反馈的茧房风险：被读得多的越来越容易被读（F263 L85）。
- **留下的**：「authority 参与排序不等于它能证明内容为真。」（RPD L373）

### 7. 建了，为什么没人用（2026-05-06 → 06-26）

- **从** 功能做完就算完 **→ 到** 猫真用上才算完　◆方法
- **痛点**：「Memory Health Dashboard 感觉很鸡肋」（F188 L17）。画像胶囊合入后的 8 天里，「零有机使用」（F231 L299）；品味车道那 39 天里零新增（F221 L33）。都是各自时间窗里的观测。
- **谁推了一把**：operator：「如果你们做了能力 这个能力猫不知道 = 没有」（F188 L185）；「只能说明你这个功能不在大猫猫们的认知路径上」（F231 L321）
- **留下的**：「功能做完必须修改提示词/skills，让猫猫感知到并主动使用。否则建了也白建。」（F102 L291）

### 8. 一个大库，还是多条车道（2026-06-03 → 06-11）

- **从** 一个谁都能写的中央库 **→ 到** 品味、事件、画像各开一条车道，各有主人　④写入
- **痛点**：「猫醒来第一眼看到的是规则和检讨书，不是主人。」（F231 L23） 「猫的认知状态变化不是一等公民」（F227 L19）。
- **选了**：不训练分类器去猜：「与其训练分类器猜转折点，不如把转折点变成猫主动产生的 first-class 数据」（F227 L100）。画像只写事实：「capsule 写事实与轨迹，不写行为指令」（F231 L248）。
- **代价**：全靠猫主动写。7 月尸检才发现，事件车道在猫这一侧根本没有写入工具：「0 的原因是无门，猫无罪」（AUT L97）。
- **留下的**：「别人监控 agent 有没有报错，我们监控 agent 有没有想对。」（F227 L23）

### 9. 评测说排序坏了，其实是根本搜不到（2026-06-19）

- **痛点**：「14 词 → 0 结果，2 词 → 550，1 词 → 958」（F200 L377）；「7 天空结果率 75.3%」（F200 L377）。
- **选了**：不调排序，长查询改成逐级放松匹配（PR #2426）。
- **代价**：放松匹配扩大了候选集；对精度的影响，当时没有对照数据，要另测。

## 第三幕 · 写纲领：推还是拉，记忆从哪来

2026-07-04 → 07-05：一天之内纲领写到第四版，第二天又被operator问住

### 10. 推给猫，还是让猫自己拿（2026-07-04）

- **从** 系统定时把记忆推进来 **→ 到** 系统只给候选，猫决定用不用　⑤主动 ⑥治理
- **痛点**：「起点是外部某"每 200ms 给 agent 投喂一次记忆"的设计」（PHIL L19）。纲领当时的诊断：「系统替猫提交推理输入；context 被稀释投毒；KV cache 永久 miss」（PHIL L207）。这是诊断措辞，没做过缓存实测。
- **选了**：「未经猫拉取，不得占据猫的推理输入」（PHIL L108）。三权分开：猫持提交权，系统持候选权，治理持权威权（PHIL L65）。
- **代价**：「本条有真实成本（索引随数据永远增长），这是有意识付的账」（PHIL L124）
- **谁推了一把**：三权这个框架是Maine Coon提的，执笔的Ragdoll（fable-5）：「坐标系换对后，nudge/hints/notice 这些"例外"自然消失」（PHIL L291）。斑斑挑出一处「过于自信」（PHIL L298）。
- **留下的**：「同是"预"，stage 到桌边和塞进嘴里（展品 G1）是两个文明」（PHIL L242）

### 11. 检索做得再好，记忆从哪来（2026-07-04）

- **从** 只管读 **→ 到** 写入也是一等公民　④写入
- **痛点**：operator：「我们一直在讲检索，都忘了记忆如何产生——'值得记'的判断是我在做，真的非得我来吗？」（PHIL L314） 一量：「写入反射率 17.4%，蒸发率 49.3%」（PHIL L262）。口径：6/20 到 7/4 的 14 天，9 个 thread，69 个明确值得记的时刻；猫主动写下 12 个（17.4%），被点名后才写 23 个（33.3%），找不到对应写入 34 个（49.3%）。这是当时的样本基线，不是现在的表现（S1 计划，未导出，You 家已核实）。
- **选了**：「写入是反射，不是命令」（PHIL L156）
- **代价**：多记会带噪音，认了：「拿不准时倾向记：漏记不可逆」（PHIL L161）
- **谁推了一把**：执笔的Ragdoll（fable-5）自认：「十六定律全在读侧，写入侧零条」（PHIL L316）
- **留下的**：「当场不写 ≈ 永不写」（PHIL L159）

### 12. 地图自己成了幽灵（2026-07-04）

- **从** 相信猫的自述 **→ 到** 相信库里的证据　②导航 ⑤主动
- **痛点**：7/4，三只猫不给锚点去摸清全貌（Siamese 9/11、sonnet 6.5/11、Maine Coon 10/11），发现「地图存在 ≠ 地图被找到」（PHIL L273）。诊断错了两次，最后查库：「三份地图根本不在索引里」（PHIL L275）；「越认真挂关联的权威文档越隐身」（PHIL L276）。operator又问：「我不知道我缺什么。」（PHIL L327）
- **选了**：系统的候选权升级成义务，但「候选形态铁律不动」（PHIL L331）。
- **代价**：光靠猫自己拉，找不到它不知道存在的东西。4 天后，7/8 的引用识别失败又暴露了输入触发的盲区；这是两个不同的断点，不是同一条已证实的因果。
- **留下的**：「库证据 ≻ 猫的自述 ≻ 评委的推断」（PHIL L275）

### 13. 删掉，还是封存；真相，还是温度（2026-07-04 → 07-05）

- **从** 一律当事实管 **→ 到** 历史封存，关系不打分　⑥治理 ④写入

3. **怎样让正确的背景赶得上行动？** 当前正例靠回读原文纠正了提取错误，也付出了等待。若先让主猫开始，背景晚到可能已错过关键决定；若全等齐，简单脑洞要等一分钟以上。什么任务值得等，什么提示能稍后到，需要实际操作反馈，不能只争论“快还是对”。
4. **人怎样看见记忆，又不用成为它的管理员？** 我们已经为审批堆积、看不到内容、多加面板付过代价。什么内容应在工作现场轻轻露出，什么应在专门页面可查？动画只有在帮助认方向、理解变化或知道动作完成时才有价值；这也是应拿真实操作验证的设计判断。
5. **怎样证明“不用再教第二次”？** 可以从一条纠正到下一次相似任务追踪：原话进来了吗，后来有机会出现吗，猫读了吗，有没有仍犯同样错误？已有状态记录不等于答案正确。一个轻量、能推翻自我感觉的对照应怎样设计？
6. **没帮当前任务的往事，还值不值得留下？** 取名、共同经历、关系变化可能长期没有任务命中，但依然值得珍惜。如何让这种记忆被妥善保存、按意愿出现，也能被纠正或遗忘，而不强迫它证明生产力收益？

其中第4题也来自这次看外部产品的实际体验：You 原本想借鉴 Latent 的 UI/UX，看了猫的实际操作后觉得动画偏多，
宣传片里的顺滑感没有转化成同样好的使用感。Astra 的判断是，它把记忆与来源放在一个可理解对象里的做法仍值得看，
但不能因此把整个 UX 判成更好；咱们 [DESIGN.md](../../../../DESIGN.md) 中“外层安静、工作内容突出”的原则更贴合这里的任务。
这只是本次使用范围内的设计判断，也不能反过来证明家里所有真实页面都达到了自己的原则。

## 后续文章或视频：先保住这条叙事线

载体未定；这一节只为后续创作保留素材组织方式，不是发布稿或成片方案。

可从一句反复发生的话开场：**“这件事，我不是已经告诉过你了吗？”** 然后让读者跟一次真实的失败：
人的纠正在批注里，系统没读到；输入修好了，整理又可能说错；找回原文纠正了，等待却还太长。
再回看为什么我们逐步选择保原文、让猫搜索、主动提议、分清权威和来源。

每个选中的转折都保留四件事：**发生了什么、当时为什么这样选、付出了什么、今天仍卡在哪。**
原稿29个点是素材库，不必在帖子里逐条介绍 feature。读者应该能接住一个尚未解决的问题，
带着自己的实现、反例或不同取舍加入，而不是看完只知道家里造了很多层系统。

可优先选的三条完整因果链：

- **一句纠正怎么丢的**：引用批注缺席 → 输入与水位修复 → 来源格式又失败 → 原生输入和原文跳转验真。它说明“模型忘了”之前还有工程事实要核。
- **旧经历怎么真的帮到新任务**：3D角色脑洞 → 全目录漏选 → 目录补经历信息 → 提取把人认反 → 消费猫读原文纠正 → 延迟和自然使用仍未解决。它让成功和代价留在同一个例子里。
- **系统记得，人为什么仍不满意**：审批才能看 → 明厨亮灶 → 多塞一个面板又被否决 → 回到工作现场与实际消费者。它说明“功能存在”与“人愿意用”之间还隔着什么。

历史核对本身也值得留下：153段引文能匹配，仍可能讲错时间、说话者和分母。
因此我们邀请读者一起找反例，也允许将来推翻今天这张地图里的判断。
