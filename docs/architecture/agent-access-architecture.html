Agent 插件化架构

Host 定义会话、能力和渲染数据。 各 client 的 adapter 翻译原生协议，界面读同一套 Host 数据。

本页描述 PR #2030 的候选实现。已有旧版 Host 需要一次接入切换，才能加载和调用这份 Agent Access。

Host 怎样定义一个 Agent

先选定一个 Agent 的会话实现，再拿到能力描述和结构化事件。适配层位于原生协议和 Host 之间，负责把不同 client 的语义翻成 Host 能理解的输入、能力和输出。产品界面消费 Host 的数据投影。

原生 clientACP 握手和通知、SDK 回调、CLI 事件、远端 A2A。
Client adapter解析原生能力，翻译命令和事件。实践中分布在 Agent Access Worker 和 Host 的承载适配器。
Host 会话契约注册实现，调用会话/回合操作，读取能力和有序事件。Host 核对身份与权限。
Host 数据投影配置面生成目录/选项；执行面生成 AgentMessage 及其他 UI DTO。
成员设置与聊天按选项和状态渲染配置，按事件类型渲染文本、工具卡、错误和终态。

新 client 用什么契约接进来

先看新 client 能否提供现有 Host 能承载的 ACP 会话。插件的包类型要与 Host 的接入点匹配。

已有标准 ACP client

接入包可以只放声明。 前提是 client 已可在本机由 Host 启动，能说现有宣告路径支持的 ACP stdio。手动配置通用 ACP 时也可直接指向这个 client。

  1. 用兼容 manifest.json，在包根放 agent-provider.json。
  2. 声明稳定的 id、transport: "acp" 和 acp.command/startupArgs，可加 configurationKey 让 owner 保存连接配置。
  3. 安装启用后，成员绑定 plugin:<pluginId>/<id>。Host 注册到 SessionImplementationRegistry，用通用 ACP adapter 转成 Host 的会话与事件。

声明解析 ↗ · 激活注册 ↗

只有 SDK，外面包一层 ACP

用现有扩展点。 单独安装一个可执行 bridge。bridge 用 SDK 访问 client，并在外侧实现 ACP 握手、会话和提示请求，在确实支持时报告恢复、图片或配置能力，输出标准 ACP 通知。

  1. bridge 翻译 SDK 回调为 ACP 更新，保留可证明的会话身份和终态。
  2. 用同一声明包指向这个已安装的 bridge。Host 继续复用 ACP adapter 和现有界面。
  3. 核打开、流式、取消、重启续接，以及模型与设置是否端到端生效。

ACP 能力协商 ↗ · 现有安装回归 ↗

只有 SDK，直接接 Host

需要开发 Host 适配。 现有声明只接受 transport: "acp"。通用插件运行时可以执行模块动作。Agent 注册表的现有插件入口仍按 ACP 声明创建 Host 实现，模块启动端口没有提供注册表。

  1. 按 Host 的 AgentService 或内部 AgentSessionProvider 写 SDK 承载，接入 Host 的构造路径或注册表。
  2. 将 SDK 的调用、能力和事件翻译成 Host 数据，保留原生事实与取消语义。
  3. 如果要支持「安装原生 SDK 包即可注册」，还需公开版本化 adapter 契约、注册/卸载和授权挂点。

一轮 DSH 对话如何跨过三层

以支持原生 L0 的 Windows DSH 为例。

  1. Host解析 @成员，准入，冻结本轮角色、账号和工作区
  2. Host用冻结输入编译 L0，计算本轮启动配置代际
  3. Host按代际复用进程。需要冷启动时先写入并核验私有 L0 补丁，再启动子进程
  4. Worker冷启动先 initialize。首轮新建会话，续聊按原 ID 执行 session/resume
  5. Host → WorkerHost 提交本轮 user 输入，Worker 发 ACP prompt。合格版本的当前 user 无额外 L0 前缀
  6. DSH → WorkerDSH 组装模型请求，personaPrefix 进入 system。Worker 读取 ACP 事件
  7. Host校验并归一化 AgentMessage，回传与持久化。角色变更按新代际启动，原会话 ID 可续接

兼容分支 未验证原生 L0 的 Desktop 版本告警并沿通用 ACP 的 user 前缀。通用 ACP 的 load / resume 按客户端能力判断。角色 A 的旧 user 历史保留，新一轮用角色 B 的 system。
