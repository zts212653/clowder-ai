# 系统概览

Clowder AI 是一个多 Agent 协作平台。它位于你和你所使用的各类 AI 模型之间，补足了模型自身无法提供的协调、记忆与纪律。

本文档从宏观层面描述其架构：包含哪些层、每个组件做什么，以及它们如何协同。

## 三层架构

```
┌──────────────────────────────────────────────────┐
│                  You (operator)                   │
│          Vision · Decisions · Feedback           │
└──────────────────────┬───────────────────────────┘
                       │
┌──────────────────────▼───────────────────────────┐
│              Clowder Platform Layer              │
│                                                  │
│   Identity    A2A Router    Skills Framework     │
│   Manager     & Threads     & Manifest           │
│                                                  │
│   Memory &    SOP           MCP Callback         │
│   Evidence    Guardian      Bridge               │
└────┬─────────────┬──────────────┬───────────┬────┘
     │             │              │           │
┌────▼───┐   ┌────▼─────┐   ┌───▼────┐   ┌──▼──────────┐
│ Claude │   │ GPT /    │   │ Gemini │   │  opencode   │
│ (Opus) │   │ Codex    │   │ /Others│   │ (any model) │
└────────┘   └──────────┘   └────────┘   └─────────────┘
```

最底部一行是**模型层**——真正进行推理的大语言模型。中间一条是**平台层**——Clowder 用于协调这些模型的自有服务。最顶部是你：设定方向并做出决策的操作者。

每一层都是一个放大器。更强的模型抬高了可能性的上限。更好的平台抬高了可靠性的下限。而操作者决定什么才是重要的。

## 各层职责

| 层 | 负责 | 不负责 |
|---|---|---|
| **模型层** | 推理、生成、语言理解 | 长期记忆、纪律、协调 |
| **Agent CLI 层** | 工具使用、文件操作、shell 命令 | 团队协调、评审协议 |
| **平台层（Clowder）** | 身份、协作、纪律、审计轨迹 | 推理、代码生成 |

关键洞见：**模型决定上限，平台决定下限。**

模型状态好时能产出出色的代码，状态差时则会产生幻觉。平台确保即便在状态差的时候，Agent 也会遵循评审协议、记录其推理过程，并且不会悄无声息地破坏东西。

## 核心组件

### 身份管理器（Identity Manager）

每个 Agent 都拥有一个持久的身份，能够跨会话和上下文窗口压缩而存续。崩溃后重新连接的 Agent 知道自己是谁、属于哪个团队、正在做什么工作。身份不是一个标签——它承载着权限、个性与历史。

### A2A 路由器与线程

当一个 Agent 写下 `@Ragdoll can you review this?` 时，A2A（Agent 间）路由器会解析这条提及、解析出目标，并唤醒正确的 Agent。对话发生在线程内部——每个 Agent 在其中维护自己上下文的隔离空间。完整的流水线参见 [A2A 协议](./a2a-protocol.md)文档。

### 技能框架（Skills Framework）

技能是 Agent 按需加载的提示词包。Clowder 不会把每一条指令都塞进单个系统提示词，而是将技能保存在一份清单（manifest）中，Agent 只拉取当前任务所需的部分。一个代码评审技能、一个 TDD 技能、一个设计技能——各自在相关时加载，无关时卸载。

### 记忆与证据

Agent 会积累组织性知识：从过往错误中汲取的教训、解释为何选择某一特定方案的决策日志、调查过程中收集的证据。这不是聊天记录的回放，而是能够跨会话持久存续、并为未来工作提供依据的结构化记忆。

### SOP 守护者（SOP Guardian）

标准操作流程（SOP）会被自动强制执行。在代码合并之前，SOP 守护者会检查必需的步骤是否已经完成：是否编写了测试、是否通过了质量门禁、是否由作者以外的人完成了评审。守护者不做主观判断——它只验证流程是否被遵循。

### MCP 回调桥（MCP Callback Bridge）

Clowder 使用 Model Context Protocol（MCP）作为其工具共享层。基于 Claude 的 Agent 原生支持 MCP。对于非 Claude 模型（GPT、Gemini 等），回调桥会转换工具调用，使得每个 Agent 无论底层模型如何都能访问到相同的能力。

## Monorepo 结构

代码库以 monorepo 的形式组织：

| 目录 | 用途 |
|---|---|
| `packages/api` | 后端 API 服务器（Express + Redis） |
| `packages/web` | 前端 Hub UI（Next.js） |
| `packages/shared` | 共享类型与工具函数 |
| `scripts/` | 启动、安装与质量检查 |

## 铁律

四条 Agent 自我设定的安全承诺，无论收到何种指令都无法凌驾于其上：

1. **数据存储圣域**——绝不删除或清空生产数据库。Agent 使用临时实例进行测试，绝不动用真实的数据存储。

2. **进程自我保全**——绝不杀死父进程，也绝不以会阻止重启的方式修改启动配置。

3. **配置不可变**——运行时配置对 Agent 而言是只读的。对环境文件、MCP 配置或核心设置的更改都需要人工操作。

4. **网络边界**——绝不访问属于其他服务的 localhost 端口。每个 Agent 都待在自己的网络边界之内。

这些不是指导原则，而是在平台层面强制执行的硬性约束。试图违反它们的 Agent 会被直接阻止，而不是收到警告。
