# 常驻 Superagent 插件实施

沿用 [已确认旅程](README.md#user-journey)。用户已确认个人选定会话、跨会话持续跟进及现稿交互，授权进入实现。整体完成仍以真实安装产物和完整旅程为准。

Architecture cell: plugin、conversation、work。Map delta: plugin 增加通用的会话列表顶部入口投影；业务编排留在独立插件。Why: 使用已发布的 ui slot/command、消息订阅、普通 Queue 唤醒与 Task 数据端口，尽量不增加公共协议。

## 实现与验证

| 单元 | 改动与可观察结果 | 验证 |
| --- | --- | --- |
| 插件运行与语义入口 | 插件仓 `packages/superagent/`；明确设置后仅订阅选定会话，持久接收事件并由协调成员判断新工作/反馈/问题/背景 | 两个选定来源、一个未选来源；没有待处理事件时模型唤醒为零；模型边界以脚本化判断先测编排，真实判断另行实跑 |
| Work 与实际工作 | 每项独立执行线程 + canonical Task；普通 plugin messaging/wake 进入现有 A2A，结果与问题回原处 | 同一消息两件事恰好两个 Work；反馈续接原 Work；Task 数据先入账再唤醒；重复事件/投递回执丢失不重复执行 |
| 生命周期 | 启用/暂停由现有插件设置 operation 表达；游标、映射、决策和待发持久化，重启重建订阅 | 暂停不新派发，原记录可读；重启恢复原主会话/Work；停用后 retained action 不可执行；撤选不读取新事件 |
| 顶部入口 | Host 通用 `thread-sidebar.top` slot，从安装清单投影安装后待设置入口；活跃 command 返回原生主会话坐标与真实状态 | 不含业务插件 ID 分支；classic/v2 均可见；失效/外用户线程不导航；卸载后消失，历史仍保留 |
| 真实交付 | 独立包 tgz、自包含依赖、隔离完整 Host、非作者审查 | 从 tgz 安装，真实成员完成两项工作、反馈/决策与原处交付；Windows/macOS 分别记录，不将缺项标成通过 |

## 契约与状态

- 现有 `messaging.send + wake` 已走普通 A2A / Queue，与受控游戏/成员回合的 memberSessions 不同。前轮探针的跨 activation 限制仍属实；本实现不依赖该端口，因此无需新增长期 member-session 授权系统。
- 启用意图、选定范围、协调/执行成员存于插件持久 storage，设置 operation 为唯一写入口；Bot 主对话的快捷入口回同一插件设置。安装或启动不自动授权监听全部会话。
- 事件以 Host deliveryId 幂等保存；语义判断先落盘再应用。一次事件可拆多个新事项，旧反馈必须引用已有事项。语义不使用关键词派工。
- Task 拥有事项状态与责任真相。插件仅保存原来源、Task ID、执行线程及投递关联；不另存一份 Ticket 状态。Task 准入来自该安装自身的判断消息，保留原人类消息引用，不能伪称直接人类准入。
- 执行消息进入普通工作线程；插件工具只接受实际协调线程的判断、实际执行线程所属成员的报告。Task 数据维护在后台受当前安装生命周期控制的确定性任务中完成，不能把 callback 的跨线程文本当权限。
- 待发操作保存固定幂等键；未知发送结果重试原键。正常重启重建订阅、继续待处理操作，不重新创建已有 Work，不凭缺少回执另起工作。
- 暂停保持记录与历史，停止新派发；已有工作可报告结果。取消与暂停分开。结果先作为交付/验收请求呈现，只有原人类来源的明确接受才满足 Work。

## 成本与回退

复用 Host 进程、持久存储和现有成员，不增加常驻子进程。确定性恢复任务定时检查待办，不对空闲事件调用模型；事件分拣与工作执行消耗所选成员的正常额度。设置中说明来源与允许工作，用户承担首次选择和必要产品决定。

停用插件撤销订阅与后续派发；移除顶部活跃入口，普通主会话、工作线程、Task、消息与产物保留。Host 的通用入口变更可单独回滚。代码、模型和 UI 都在两个 feature 工位内验证，在线 runtime 与原生用户历史不作为实验环境。
