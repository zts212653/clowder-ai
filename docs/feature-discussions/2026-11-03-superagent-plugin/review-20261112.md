# PR #1825：入口读取与稳定导航修订

本轮沿原 PR 处理 [zts 的 issue 意见](https://github.com/zts212653/clowder-ai/issues/1860#issuecomment-6651888944) 与 [最新复核](https://github.com/zts212653/clowder-ai/pull/1825#issuecomment-6813249556)。保留“安装后即能发现、尚未配置时进入原设置”的顶部 Bot 入口；不将其替换为必须先有会话的普通置顶功能。

## 对意见的判断与实现

1. **采纳后台 command 副作用与挂起问题。** `GET /api/plugin-conversations` 改为只读取 Host inventory、运行健康和已确认绑定，完全不调用插件代码，删除 15 秒轮询。挂起或有副作用的普通 UI command 不再因读取列表而执行，无需为这条读取链新增一套可轮询的插件 action 或 deadline 协议。
2. **采纳 Host 受控绑定。** 使用原 UI contribution 的静态标签和设置地址。用户首次明确打开已启用入口时，调用对应 command 获取原生 thread，验证 owner 和删除状态，再由 Host 持久保存 `{role: main-conversation, ownerUserId, commandId, threadId}` 于对应 `pluginId/pluginInstanceId` 的 instance record。插件不能写自由格式 binding。后续点击直接使用该原生会话；没有绑定时进入原配置流程，不新造会话身份。
3. **采纳启用意图与健康分离。** 顶部只投影 Host 可以确认的待设置、未启用、启动中、可用、不可用；`enabled + crashed/degraded` 显示不可用。监听/暂停及业务待处理项继续由插件自己的设置和原生会话承担，不把上次 command 返回的业务状态伪装成实时健康。
4. **采纳稳定导航与去重。** 浏览器读取或解析失败只标记不可用，保留最后确认的 threadId；Host 的暂时存储读取错误也保留该 owner 的已确认坐标。Host 明确读到线程删除/不属于 owner 才不再提供目标。顶部已展示的原生 thread 不在普通列表再出现；instance 退役后顶部撤下，原生会话重新由普通列表承接，历史不删除。
5. **保留已有通用修复。** Queue 已公开消息的补发布和归档安装的 120 秒截止保持原合同。同步当前 `next` 使用普通 merge，保留原 PR 和已公开提交历史，不 force push 或另起平行实现。

绑定为可选持久字段，旧 inventory 没有该字段时按未绑定处理；没有 schema 迁移、TTL 或另一份用户业务 Task 数据库。绑定只是导航关系，不授予插件读取其他用户线程或自动执行任务的权利。打开绑定的 POST 仍要求直接 localhost 的认证 owner 写请求；匿名和外部来源在运行 command 前拒绝。

## 验证与证据边界

先在原实现复现 3 项 API RED：列表执行普通 command、挂起 action 阻塞列表、crashed 错报 disabled；前端另复现读取失败后原生按钮消失。修正后入口、绑定往返/停用/删除、owner 保护与请求授权检查通过；Queue 与原插件资源分发回归仍保留。

`superagent-resident-navigation.mjs` 使用真实 `ThreadSidebar`、原生行、HTTP client 和生产样式，在 classic/v2 执行首次明确打开、普通列表去重、读取 503 后继续打开原会话、instance 退役后普通行恢复。全部网络由既有浏览器 harness 截获，不访问运行实例或模型；浏览器产物记录 page error 和意外请求，不以 JSDOM 断言代替真实渲染。

安装组合检查经真实 TGZ Manager、消息/Task/线程端口验证，并新增“明确打开后持久绑定到该实际主会话、Host 组合重启后仍保留绑定”的断言。该检查使用独立 Redis/数据路径和脚本化成员，不能当作真实模型语义或 macOS 产品验收。

同步当前 `next` 后，原安装 TGZ 首次组合检查因 `Invalid Superagent delivery` 失败。根因是 Host 已采用 `0.3.3-candidate.1` 的 `reason` 字段，旧包仍捆绑严格的 `candidate.0` 校验。插件仓当前已合入的 main 已更新依赖及持久收件兼容；后续组合验证使用该已合入版本的新物化包，不修改 Host 投递协议，也不静默剥掉 `reason`。旧失败及旧包保留，不将其改写为通过；桌面旧安装并未在本轮自动升级。

issue #1860 后补的“异常监督→原负责人接责→有限重试/换人”仍是未通过的插件能力验收，不在本 Host 入口修订中冒称已修复。macOS 产品验收、合并后隔离验收和 runtime 部署仍分别记录；本轮没有改动在线实例。
