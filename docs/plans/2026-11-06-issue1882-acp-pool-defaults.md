# Issue #1882：ACP 默认进程容量政策提案

状态：提案，等待维护者决定。目标分支：`next`。
公共来源：[Issue #1882](https://github.com/zts212653/clowder-ai/issues/1882)、[PR #1889](https://github.com/zts212653/clowder-ai/pull/1889)、[维护者反馈](https://github.com/zts212653/clowder-ai/pull/1889#issuecomment-6682845281)。

## 问题与拟议政策

通用 ACP 池当前在未配置容量时采用 3。当三个进程都持有活动租约时，第 4 个请求会得到 `Pool at capacity`。这个数来自 Host 的默认资源政策，不能据此认定 DSH 或其他 ACP 客户端原生最多只能运行三个会话。

本 PR 提议区分通用客户端与现有 Gemini 路径：

| 配置 | 拟议有效容量 |
| --- | --- |
| `clientId === 'google'`，未显式配置 | 3 |
| 其他 ACP 客户端，未显式配置 | 20 |
| 任意 ACP 客户端，已配置正整数容量 | 显式值，例如 10 或 8 |

例外使用现有客户端身份识别，不按昵称、模型名或命令字符串猜测。通用 `clientId: 'acp'` 接入的程序采用 20；CLI/native 路径不受该函数影响。

## 适用依据与维护者决策

提高通用默认值的收益是给多个活动线程更多并发余量，避免第 4 个请求仅因继承的 Host 默认值而立即失败。Gemini 保留 3，减少既有特殊接入路径的资源政策变化。容量仍按需使用，不会预启动 20 个进程。

**20 是本 PR 提议的资源政策数值，不是压测得出的通用安全值。** 当前证据能证明 Host 正确执行该上限，不能证明它适合所有机器或所有客户端的活动负载。选择 20 而非其他较高整数，仍需要维护者的产品取舍；本方案不将单个安装实例的偏好视作公共项目已经采纳的决定。

需要公开确认的决定是：是否接受所有未配置的通用 ACP 成员采用每成员 20 的名义容量，包括当前不能单独声明 pool 的插件客户端。另一条可用路径是继续默认 3，由支持池配置的成员显式设为 20；这条路径无需本 PR，但仍保留较低的通用默认值。公共维护者尚未批准前，不将本提案记为已采纳或可合入。

## 资源代价与边界

- 一个成员满负荷时可比原默认多持有 17 个进程；多个成员的容量会叠加。这不是 Host 全局进程预算。
- 更多活动进程可能增加内存、模型请求以及原生工具/MCP 连接和子进程峰值。客户端、模型上下文、工具集合不同，成本也不同；尚无可公开核验的代表性活动负载峰值测量。
- fake client 的 acquire 测试只证明数量限制、显式值优先和超限拒绝，不能作为上述资源峰值的证据。空闲 ACP 进程测量也不能替代活动会话及工具调用的成本测量。
- 不启用 multiplex，不改 idle TTL、回收、失败回传，不抢占活动进程，不迁移已保存的显式配置。容量等待、有限重试和耗尽后 caller 接续仍由 Issue #1882 跟进；本 PR 使用 `Refs #1882`，不关闭该 issue。

## 实现与配置

1. shared 的 `defaultAcpPoolMaxProcesses(clientId)` 返回 google=3、其他=20，仅用于 ACP。
2. 工厂按显式值 ?? 客户端默认值解析一次，将同一值用于 spawn signature 和新池构造。复用既有 retirement/drain 逻辑。
3. 两个现有成员编辑入口共用该函数作为容量占位符；输入留空时不把默认值写入保存内容。设置页直接渲染容量 TextField，不扩展通用字段三元组。
4. 原有字段可见性保留：plugin-managed ACP 隐藏容量字段，官方 AGY ACP 在设置页也保持隐藏。插件声明的严格 schema 当前不接受 `pool`，不能建议向插件 client 配置添加该字段；在当前声明能力下，此类通用客户端采用 Host 默认值。
5. 普通 ACP 成员若已有显式 10，将继续使用 10；要采用 20，可改填 20，或清空以跟随默认。不替用户执行配置迁移。回退可以撤销本 PR，或在支持配置的成员中显式设置较低容量。

## 验证与未验证范围

- 工厂容量矩阵：通用 ACP、Pi、OpenCode 为 20，google 为 3，显式 10/8 优先；实际调用生产工厂与 pool.acquire，下一次 acquire 超限拒绝。基线三个通用默认用例失败，实现后 6/6 通过。
- API 相关 factory/pool/signature/registry/account-source 回归 60/60；Web 编辑器、运行契约和默认值测试 91/91；shared/API 构建与 shared/API/Web 类型检查通过。
- Windows 容量 fixture 使用隔离 HOME 与既有 trusted-host 测试模式，不作为严格启动隐私边界验收。Web 当前表单客户端类型不包含 pi，其容量由后端用例覆盖。
- 真实编辑组件与 payload builder 的隔离浏览器验证覆盖 20/3 切换、显式 10 同步保存、清空不写容量。完整设置页的本地预览遇到既有 CSS 编译问题，因此仅记录组件验证；没有 20 个真实 DSH 活动进程的容量压测结论。
- 各次提交的公共 CI、审查和合入状态以 PR #1889 为准；实现测试和代码审查不代替默认资源政策的维护者决定。
