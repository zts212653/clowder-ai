# #1773：关键资源 reader 窄修

砚砚与鲸鲸独立分析、交叉复核后，确认四处环境相关残余值得修。
基线：`upstream/next` 的 `3569a9b6422723faf3a586b68232c140f84b44a1`。
关联 [#1773](https://github.com/zts212653/clowder-ai/issues/1773)。

普通 Medium 权限、链接完好时四处均正常；没有用户覆盖率数据。
受控 `EnforceRedirectionTrust` 下，不可读的 junction 会同时破坏三条 agent 功能线。
这不是普通用户必现或全局启动故障的声明。

| 项目 | 已观察失败 | 修复与兼容边界 |
| --- | --- | --- |
| Claude 默认 MCP | 项目入口不可读时返回 undefined，冻结 MCP 配置跳过 | 原候选顺序保留；只在必要时回退到已声明安装根。构造参数和环境显式路径不变。 |
| AGY ACP | guard 导入失败使普通非 MCP 操作被拒绝 | 使用与 Native 同源的已打包脚本。目标、只读、会话、有效期、autoApprove 和服务器范围策略不变。 |
| Concierge Live | collab/memory 入口检查失败 | 随包二进制走安装根，cwd 走既有 active project root，与 docs allowlist 同源。凭据和工具门控不变。 |
| 插件内置头像 | 缩略图为空 | 组合根的内置 avatars 改走安装根；上传路径、格式、48px/10MB/1200 字符限额及边界检查不变。 |

四处仅改读取坐标，不删除兼容链接、不复制 packages、不改安装器、ACL、数据格式或用户状态。
无需统一资源解析框架；不增加依赖或必填工作目录参数。
回退为撤销这组代码提交，不迁移用户数据。

## 验证证据与边界

- 新增生产入口回归测试：Claude 在独立安装根可用且项目无入口时发现 MCP，保留旧入口优先和无安装根行为；AGY 在无 scripts 的项目允许普通操作且仍拒绝保护目标、只读/失效/错会话/不自动批准；Live 的二进制、cwd 和文档权限分离。
- 同一测试集在修改前 3 项失败，修改后 3 项通过。
- API 类型编译通过；上述测试与 Claude/AGY/ACP 相关既有测试共 83 项通过；Live 配置与实际文件工具边界 4 项通过。
- Windows 真实链接 RED：隔离旧包 `917120d5` 安装成功后，由 Medium Desktop 创建真实项目根；普通读取正常，Guard 下 packages/scripts 读取失败、Claude 入口为空、AGY 普通操作 reject、Live 配置失败、头像长度 0。没有执行模型或写文件工具。
- 该旧包的 AGY 策略早于当前源码；不以其保护目标判断代替当前策略的拒绝回归。
- 新候选包首装、升级、重启、MCP 握手、配置来源一致性和实际头像端点证据仍需补齐；在这些结果齐全前不关闭 issue。
