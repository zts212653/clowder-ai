## 4. 必跑的真实宿主旅程

每项覆盖桌面/390px、中/英，沿真实入口与返回导航走。新宿主内 fixture 可验证交互；真实账号/调用用另一份报告，不混记。

| 旅程 | 输入与操作 | 必须观察到 |
|---|---|---|
| J1 首启 | 0、1、多个工具；未登录/未知/可用；缺工具安装指路 | 原位刷新探测，必要登录后推荐猫，勾选确认再建成员，进入正确对话 |
| J2 主动添加 | 成员表→模板/空白→改推荐工具→保存→回表 | 名字/头像/职责保留，模型/强度继承，成员和状态正确 |
| J3 日常编辑 | 只改强度，切成员/离开/去登录，返回保存，再单项恢复 | 草稿还在；账号、模型、其他字段逐值不变；浮条一直可触达 |
| J4 F320 | 第二身份创建、失败、同条目重试、选择公司号、覆盖/恢复、换号、刷新 | 一套账号列表；attempt/token 正确消费；刷新还原真实绑定 |
| J5 旧成员 | 旧服务账号+ACP+语音/外观/上下文策略，改名；再尝试切换并取消 | 正常状态，无损 round-trip；取消无请求写入；旧程序/argv/profile 完整 |
| J6 故障 | 未安装、未登录、模型目录失败、模型拒绝、revision 冲突、部分保存失败 | 原位可恢复；显式选择不被替换；准确 dirty/已保存状态，无假成功 |

额外回归：同工具两成员并发、不同账号进程隔离、旧登录 attempt 迟到、previewToken 失效/重放、切页返回丢失 focus、输入法遮挡保存、主题切换、旧深链、已有 pin。

普通和已压缩 Codex 会话：先建立可核验上下文→确认压缩状态（对应场景）→在同 Clowder thread 换身份→提出依赖此前决定的问题→验证真实回复与原生恢复证据。只检查关键词回显不足以证明上下文接续。

## 7. runtime 交付与回退

实施后按用户先前授权更新 runtime 供验收，但本轮不执行。交付前重新读取 HEAD/status、运行进程、现有 DSH 配置和用户正在修复的现场；记录备份位置与可恢复 SHA。runtime 当前是 `runtime/upstream-main-20261010@3e70e1d68`，不是旧 native 分支。

验收 SHA 在 feature worktree 已测试后，runtime 用独立部署分支指向该 SHA，避免同一个 feature 分支在两个 worktree 强行 checkout。保留未跟踪/忽略的用户文件；遇到覆盖冲突先安排保全，禁止 reset --hard / clean 解决现场冲突。

只应用经审查的成员配置变更，先给脱敏差异与备份；不全量迁移现有成员或改写 CLI/DSH 配置。启动后核对版本、健康、三工具与关键旅程。回退代码不得回退/清空会话历史或账号存储；新字段保持向后读取兼容，必要时禁用新入口而不丢数据。
