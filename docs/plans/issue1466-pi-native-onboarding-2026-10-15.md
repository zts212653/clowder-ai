# 自动配置伙伴：暂停 OpenCode 推荐，接入 Pi

## 用户问题与本轮边界

OpenCode 的版本与默认模型选择行为存在兼容性问题，用户要求先停止自动发现/推荐，改用本机 Pi 填补自动角色位置。本轮不把地区限制报错说成已经修复，也不删除已有 OpenCode 角色、会话、认证或手动接入入口。

同时修复两项已经复现的问题：新角色错误继承 GLM 的形象/职责，以及安装实例从普通浏览器打开时将 Web5196 误推断为 API5197（实际 API3196），导致用户、作品和引导请求同时失败。

## 接入契约

- Codex 继续使用 App Server；Claude Code、Kimi 保留现有原生通道；DSH 保留 ACP。
- Pi 官方 CLI 使用 RPC，不把它直接当作 ACP CLI。产品内置薄适配层，将已有宿主 ACP 会话请求转换为 Pi RPC，复用宿主消息、工具和历史保存链路。
- 仅发现已经安装的 Pi；不在检测时下载适配器或运行用户任务。缺少可用适配入口时诚实显示未就绪。
- 模型/思考强度保持“跟随工具”；能够读取的配置展示真实标识，未读取时不猜模型。Pi 的传输标识与人类可读标签分开，不修改用户默认模型。
- 成功以 Pi 的最终稳定事件为界，不能将请求入队、部分文本、子进程启动或异常退出当作完成。取消、进程退出和多轮会话必须有独立保护。
- 宿主不支持的执行策略继续拒绝，不绕过权限边界；不能忽略 MCP 配置后宣称完整工具协作通过。

## 用户体验与兼容性

- 新推荐中用 Pi 取代 OpenCode；用户仍可选择零个、一个或多个伙伴。
- Kimi 使用其已有专属模板，Pi 使用独立昵称、职责和性格，不再借用 GLM 身份。已有自定义角色保持原配置，不静默批量替换身份。
- Kimi 已安装即可展示推荐；未知登录状态不在推荐主界面制造警告，按需登录帮助保留在折叠详情中。
- 模型来源判断与登录探测范围独立：ACP 能展示其已读取的配置，但不能因此声称认证或真实调用已通过。
- 浏览器从服务端 HTML 根属性读取经校验的实例 API 地址；Electron 桥接地址继续优先，远程代理和原认证规则保持。

## 验证与交付门槛

1. 观察旧实现的失败回归，再验证对应修复；覆盖模型来源、账号覆盖、已有角色和重试。
2. 用受控 Pi RPC 夹具检查协议、终态、取消、退出、模型切换、MCP 与执行策略。夹具不代表本机真实模型已通过。
3. 构建新 API/Web，运行正式构建后检查；普通浏览器实际核验实例端口、登录恢复、作品和引导请求。
4. 仅在授权的 clean-b / clean-delivery HOME 补充 Pi 必需配置与认证，只补缺失、不覆盖、不复制角色或会话历史。真实调用须核对目标角色、最终结果与刷新后的历史。
5. 作者已有实例升级前后逐项回读配置/旧消息；升级不算干净首装。新的完整 Setup、首次启动与引导验收继续分别记录，不搬用旧包成绩。

本文件记录本轮方案与验收条件；实际构建、安装、耗时和真实调用结果以对应回执为准。
