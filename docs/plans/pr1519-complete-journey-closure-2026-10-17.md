# #1466 / PR #1519 完整旅程闭环计划

## 目标和权威来源

用户从安装、首启演示、配置自己伙伴到实际协作均可用，异常能够恢复；存量角色、账户和历史保留。不能把“创建成功”“有登录配置”“单次回复成功”或 CI 绿灯当作整条旅程完成。

后续安装候选已经实际重编到 `0927b6d0a`，三次新目录首装与最新判定以[当前验收报告](pr1519-e2e-current-verdict-2026-10-17.md)为准。当前源码为合并main `b59cd583f`后的`6fa1689c1`，尚未制作对应新EXE；本计划下表保留实施过程，不把旧候选结果迁成新包结论。[61条逐项review回应](pr1519-review-comment-ledger-2026-10-17.md)已补齐。2026-10-17用户已明确将Claude原连接视为外部LLM API兼容问题，不再继续追查，也不要求持久启用诊断参数；保留历史失败、不全局替换协议或改模型。

## 实施顺序与可验证结果

### A. 原合同、字段与评论闭环

在本文件继续维护用户意见与 reviewer 源链接。检查现有 `docs/plans/issue-1466-implementation-contracts.md`、`docs/design/issue1466-review-closure-2026-10-14.md` 与源码，消除过时状态。确认零/单/多伙伴、classic/v2、不丢旧字段、昵称/头像和模型继承。

结果：明确每条当前是已实现已验、已实现待产物、未修或不采纳及理由；逐条回复源评论，远端回读中文正文。公开证据用 GitHub 可访问附件，不贴本机路径。

### B. 客户端与实际 A2A

- 保留 Codex App Server、Claude CLI/SDK、DSH/Pi ACP、Kimi 原生边界，不通过改工具名猜协议。
- Claude原连接的API兼容案例按用户2026-10-17决定保留证据，不再反复对照或修改产品默认协议；已有SDK实物失败不能当成替换修复。禁止静默降级模型、重写回应或放宽任务断言。
- 真调用用本次随机中文任务标记；A2A 另建作者会话，初始只唤起一个首选，观察工具传球、后继调用和最终整合，并刷新/重启回读。
- 真实工具、权限拒绝、取消和终态历史按适用 carrier 验证；不改源登录文件、不删除原会话。

结果：Clowder可正确创建、路由、执行并呈现真实A2A；产品自身失败仍阻塞验收。用户明确接受的外部API限制保留为独立边界，不伪造通过或继续作为Clowder代码阻塞。

### C. 安装与启动

先验证 `ClaudeSdkAgentService` 的未使用 SDK 静态加载；只在实际调用 SDK 时加载其运行库，保留同一个服务类、现有 query 注入、取消与异常语义。不引入替代 carrier、私有模型或并行服务 owner。测试先禁止导入 SDK，观察当前类导入的 RED，再最小修复及 F318 回归；加载期间已取消不得启动 query。

以阶段记录比较优化前后；不把 warm restart 当 cold，不承诺尚未测得的速度收益。冻结图、API bundle、资源和新 EXE 都从最终源码重建，安装包不包含认证或历史。安装器实际完整恢复与首次启动必须有对应 SHA、退出码、阶段日志及 UI 行为。

Architecture cell: 既有 agent carrier / desktop bootstrap。Map delta: none。Why: 避免未使用 carrier 的运行库进入首启关键路径，不改变身份与持久化 owner。

### D. 产物与进程收尾

盘点所有本任务 EXE、程序目录、注册项、快捷方式、服务 PID 与端口。确认归属/无活跃调用后受控停止；程序与资料逐项拆分。默认只留当前交付包、一份可用回退包和当前构建；其他候选进入可审计删除清单。保留实例 HOME、认证、Redis、SQLite、角色和历史；不按通用进程名清理。旧快捷方式归档不是卸载，须如实记状态。

干净首装作者环境与用户交付环境顺序运行，禁止同时留下多套无人使用服务。新交付不创建额外桌面入口；原唯一入口只有在版本核对后指向最新交付。保留例外有用途、负责人、复查条件和删除/停止回执。

### E. 终态门槛

目标 EXE 真正首装 → 首次启动 → 自动演示及渐进成果 → 任意配置/手动回退 → 五工具真实任务与真实 A2A → 配置修改/错误恢复 → 重启保留 → 失败 Setup 修复 → 无垃圾实例/包 → CI 终态与逐条 review 回应。
