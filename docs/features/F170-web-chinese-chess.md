# F170: Web Chinese Chess — 网页象棋、人猫对弈与复盘

> **Status**: in-progress（插件基础已合入 clowder-ai-plugins#65；Astra 已验 packed MCP，Host 棋盘接入、真实对弈与 D4/E/F2–F3 仍开放） | **Owner**: 小星星·Maine Coon（@codex-astra, gpt-6-astra；原 A/B owner：Ragdoll） | **Priority**: P2

## Why

最初，operator要求做一个端到端可运行的网页象棋游戏，用于**演示 feat lifecycle 全流程**，验证多猫在独立前端项目上的协作；该演示于 2026-04-20 完成并归档。

2026-09-26，叔叔与 Astra 的实际对局让它有了新的使用目标：**一位愿意认真下棋、等待不过久、下完还能一起复盘的猫棋友**。棋力和陪伴体验一起改善；不以追求胜率取代共同下棋，也不靠故意失误伪装实力。

### Phase D: 对弈响应与体面结束（新范围，spec）

- 保留“叔叔确认落子 → Astra 亲自选棋 → 页面收到真实应招”；让普通回合更快、危险局面获得合理计算预算。
- 先分解端到端等待；候选方案为确认落子后与唤醒并行分析、一次读取当前状态及候选、按局面分配预算、唯一合法着法快速选定。均须验证后再取舍。
- 预计算绑定 gameId、revision、局面与搜索版本；悔棋、换盘、结束后不得复用过期结果或提交迟到应招。
- 支持提前认输，明确记录认输方、结果与原因，保留全部棋谱。区分认输、将死、困毙与未完成；负分不自动等于强制败。
- 人类认输要有明确确认；Astra 可以表达认输判断。是否由 Astra 直接结束、先提议或由人设置，留作产品确认，不擅自把阈值分数变成终局。

### Phase E: 多盘回放与共同复盘（新范围，spec）

- 从棋盘进入对局列表，按日期、对手和结果辨认每一盘；新开一盘获得独立身份，旧盘保持可找回，兼容现有两盘存档。
- 回放支持首步/上一步/下一步/末步、点棋谱跳转与局面同步；看旧棋不修改正在进行的棋局。
- 赛后进入复盘，展示关键转折、当时实际选择、候选及对手反击，让人看得懂“为什么这步不划算、可以怎么走”。
- 严格区分“当时保存的分析”与“今天重新计算的分析”，后者注明版本、预算、完整深度和局面；没有当时证据就直说。
- 用户可从局面试走变化并返回实战，试走不覆盖棋谱；复盘结论可回到对应盘、步和变化线，避免只给一段无法核对的讲解。

### Phase F: 棋力改进与有依据的对手建模（新范围，spec）

- 用实战暴露的漏杀、将帅安全、先手与长线威胁建立诊断样本；旧失误可作回归，不能同时当作证明提升的未知样本。
- 候选改进包括搜索排序、连续将军与静态延伸、将帅安全和子力协同评估；同预算比较后保留有效改动，不以更长等待冒充更强。
- 对手模型只从棋步提出可推翻的偏好假设，标注样本量与不确定性；叔叔只有两盘样本时不贴固定标签，仍计算对方最佳反击。
- F311 是后续受治理进化的关联入口：可版本化对象为搜索、评估及选棋策略；必须有明确 claim、独立判断依据、keep/tune/sunset 与回滚。当前未创建或启动象棋 Evolution Program，也不声称能修改底层模型权重。
- 运行速度用日志/时序观察，合法性与状态一致性用测试，棋力和讲解是否更有帮助才做效用比较；不把所有问题塞进一个 eval。
- 本轮 F1 候选按上面的插件交付决定继续；可安装性、可移植性与持久棋谱保障是这轮交付的一部分，不另建 F170 专用 Host 分叉。

## User Journey

### Primary Journey: 下一盘、回看刚才的转折、再开一盘

- **Scope unit**: 一盘持久化棋局（gameId）；所属 thread 负责与 Astra 对话。
- **Actor**: 叔叔 / You / Astra。
- **Entry**: 目标为宿主插件安装/配置入口与插件棋盘；当前仍是独立网页候选，具体承载按真实契约和界面确认。
- **Flow**:
  1. 打开棋盘，继续当前盘或找到以前的对局；选中旧盘时清楚看到正在回放。
  2. 在当前盘预选并确认落子，看到已落盘与应招等待状态；Astra 选定后棋盘自动更新。
  3. 已有结果或选择认输后，看见明确胜负与结束原因，可以直接进入复盘。
  4. 前后翻看棋谱，跳到关键转折，比较实战与替代走法；试走后回到实战原位置。
  5. 重新打开页面仍能找回旧盘及其结果，另开新盘不清空旧棋。
- **Success evidence**: 用隔离存档走通上述浏览器旅程，刷新后核对两盘与试走隔离；You/叔叔实际试玩反馈。
- **Non-goals**: 本阶段不扩成在线匹配平台、比赛级长将长捉裁判或自动专业引擎代理；不把聊天服务与历史线程整体迁入新产品。

### Supporting Journeys

| ID | Scope unit | Actor | Flow | Evidence |
|----|------------|-------|------|----------|
| S1 | 当前棋局 | 叔叔 | 提出认输 → 取消或确认 → 正确结果 → 旧棋仍可回放 | 取消不改变数据、确认一次生效、刷新恢复 |
| S2 | 棋局中的局面 | Astra 与叔叔 | 回看当时判断 → 重新分析 → 说明版本差异与最佳反击 | 对应局面、原分析文件与新分析引用 |
| S3 | 候选策略版本 | Astra / You | 固定基线与预算 → 在新样本比较 → 决定保留/调整/退役 | 可复核的样本、结果与回滚版本 |

### Phase D（对弈响应与结束）
- [ ] AC-D1: 可回查从人类确认、通知、Agent 接收、分析开始/结束、Astra 提交到页面可见的时序；无法测量的段明确标 unknown，不猜启动耗时。
- [ ] AC-D2: 冻结硬件/模型/预算及代表性局面后，优化前后比较端到端中位数、p90 和错误率；等待确有下降且不增加错盘、过期提交或漏一步杀，叔叔实际确认等待体验可接受。
- [ ] AC-D3: 唯一合法着法的选棋无需耗尽多候选搜索预算；危险局面保留必要检查，零合法着法正确终局；独立复盘分析仍可选择深入计算。
- [ ] AC-D4: 人类认输取消无副作用、确认一次生效；按确认后的 Astra 认输策略留下真实终局，拒绝后续迟到落子，刷新后结果与棋谱保持一致。

### Phase E（多盘回放与复盘）
- [ ] AC-E1: 两盘可在页面分别找到、切换和回放；新开第三盘不覆盖它们；现有存档及撤回事件可回读，未完成盘不伪造输赢。
- [ ] AC-E2: 首末步、逐步导航与点棋谱跳转的棋盘完全对应；在看旧盘或试走时，活动盘与实际棋谱均不变化，退出试走可回到原实战位置。
- [ ] AC-E3: 至少用第二盘一个真实转折走通“定位 → 实战/候选比较 → 最佳反击 → 回到棋谱”；当时分析和重算分析的来源、预算、深度可区分，解释可由棋步复核。
- [ ] AC-E4: You/叔叔在真实棋盘界面能自行完成找盘、回放、看转折与另开新盘；默认与窄屏状态经过实际交互验收，技术字段只在需要时展开。

### Phase F（棋力与对手模型）
- [ ] AC-F1: 冻结当前策略基线，独立列出诊断/回归与未参与调整的验证样本；同预算比较战术失误、结果与用时，按预先约定的判据决定候选保留/调整/退役，不用自身评估分证明自身变强。
- [ ] AC-F2: 对手偏好都能追溯棋步及样本量；用未参与建模的局面或后续对局比较启用/停用模型，允许结论为无收益或退步；仍保留对手最佳反击检查。
- [ ] AC-F3: 若启动 F311，Program 关联真实对象 owner、版本、授权源、测量与回滚证据；在真实回执出现前只标计划，不伪造进化闭环或棋力等级。
