# F338: 会话缓存冷热与可选延长保留

> **Status**: in-progress | **Owner**: 小太阳·Maine Coon (@codex61-sol) | **Priority**: P1

## Why

导演派活后等待，队友交回时缓存过期会整段重写长上下文。派活也常只看历史作者，没有看到目标的当前会话。让猫知道目标会话的冷热，由主人决定是否为正在等交活的会话保留缓存，减少无用重写并保持判断所需的上下文。

批准来源：本线程 You `[thread-id]#private-source-id`（2026-11-16 15:23 PST）。他要求前端可感知、默认关闭、自己在前端打开，并要求告诉猫队友热不热。小导演的实现交接为同线程 `private-source-id`。同一阶段最多两个 PR，挂社区 [#2015](https://github.com/zts212653/clowder-ai/issues/2015)。

## Current State / 现状基线

11-16 的 Sonnet 原生 CLI 机制验证已完成：固定前缀下，第50分钟分叉续一次，第75分钟原会话仍命中且父历史不增加。当时尚缺完整 Host 返回验收；后续正式 SDK 机制验收见上方 11-18 记录。第二轮对照连接失败，压缩摘要受输出限制干扰，共享订阅净收益未测出。旧压缩质量试验完成A组31万上下文与真实工作校准后，因`allowed_warning`而停止；C组、压缩、返回及10次调用比较均缺测。11-17设计者明确：新质量实验可在`allowed_warning`下显式发`/compact`，须重新冻结材料、预算与热窗口，不复用旧起点；这不改变产品自动触发条件。

PR1 将实际档位和时间上下界保存在原 `SessionRecord.lastUsage`，目录与真实服务统一运行时键；预检、导航和 API 使用同一投影，保留模型依据、未知及前缀未校验的边界。默认 `-p` 路径支持观测，`bg_daemon` / `interactive_pty` canary 未声明 freshness 载体，暂为未知。普通唤醒仍不能冒充独立续约调用。

## What

### Phase A: 会话冷热与默认关闭的延长保留

**PR1：冷热信号。** 由实际调用事实记录最后请求时间及其来源、上下文大小、观测到的 TTL 档、模型/运行时、最近压缩。每段会话单独投影；按运行时 × 模型的实际用量学习保留窗口，文档只作先验。没有证据写未知，不把未知或传输失败当冷。冷热是带来源的估计，不承诺供应商缓存一定存在；不以该信号阻拦或悄悄换掉显式目标。派活前预检、每轮成员运行态及前端同用一个读模型。

**PR2：延长缓存保留。** 每猫开关默认关闭，主人显式开启才生效。仅当前 Claude 支持路径显示。先在真实 Host 绑定下验证分叉、原前缀和小尾巴，再落 UI。只在该会话派活并等待交回时续；从最后一次匹配请求计算，在期限前留余量；交回、真实回合、前缀变更、关闭或两小时上限即停。维护不发消息、不发 A2A/待办、不显示为猫在工作。维护记录持久保留，失败停止而不循环冷写。

不在本阶段：系统提示快照或家规差异送达改造、默认开启、自动改路由、稀缺席位的线性实验、修改其他线程责任、runtime/Redis 重启。八处派活路牌由小导演在 PR1 合入后负责，本 Feature 不代改其责任。

### Phase B 候选：空闲压缩与可交接的等待继续

You 19:31新方向（`private-source-id`）与时机更正（`private-source-id`），见调研稿§15、§15.6及共享决定页r3。小狐狸继续写代码，系统提示和名册不改。先研究怎样更省，不实施“移除实现作者资格”。

候选一是会话一轮结束、没有新请求、在等队友或长等时趁热压缩，绝不打断连续施工。产品自动触发仍沿用已获批的CLI条件：前缀未变、1h档且仍热、额度状态`allowed`、上下文至少20万（最低不低于10万）；与1M上下文窗口是两种门槛。是否允许产品在`allowed_warning`触发仍待You决定，不随实验放开。Sonnet质量实验则可显式`/compact`，以新冻结的真实线程与文件、不限摘要输出、约50分钟压缩/75分钟返回，比较四项找回质量及之后10次工具调用总账；实验总API等价预算5美元，未据此开启默认压缩。

候选二是“等待继续”可由指定接手猫承接，例如合入后的runtime检查交审查猫；未指定时使用冷热信号辅助，并在首页提供“交给…”动作。施工前核F337停止/续接和等待owner边界；通知、唤醒与Task责任不可混为一谈。本段仅登记候选，不扩大Phase A两个PR合同，不创建或冒充已交付的Phase B。

若后续获准实现压缩候选，恢复首轮的精确编号和原话须来自本轮读取结果，避免把重读后的转写错误当成已核出处（Opus55 11-17复核要求，调研稿§16.5）。当前不改变系统提示或名册，不因该候选提前开启产品默认值。

## User Journey

### Primary Journey: 主人打开延长缓存保留

- **Scope unit**: session
- **Actor**: You
- **Entry**: 设置 → 成员与运行时 → 某只支持的猫的详情
- **Flow**:
  1. 在「模型与接入」看到默认关闭的「延长缓存保留」和统一的问号说明；成员列表不加列。
  2. 主人开启后，猫派活并等待时，系统只在已验证的缓存窗口内做有限续约。
  3. 在「状态与会话」的上下文用量旁看到 muted 的「缓存保留至 07:00」，无工作状态色点。
  4. 主人关闭或等待结束，保留状态消失，后续没有维护请求；已有记录可追溯。
- **Success evidence**: 真实壳中默认关闭、开启等待、停止、刷新和窄屏截图；小导演先核实，再给 You 看。

### Supporting Journey: 猫派活前看目标会话

猫在当前线程的成员运行态看到队友的预计冷热、上下文大小及未知原因；实际派发前预检再读当前值。并行线程、换模型或压缩后，不沿用另一段会话的热度。显式目标保持不变。

## Architecture Ownership

Architecture cell: identity-session, routing-context, dispatch, thread-navigation, mcp-surface-governance

Map delta: existing cells updated; no second routing or custody owner

Why: 会话拥有观测事实，routing-context 只组合派活提示；独立续约调用不取得聊天/派活责任，也不改用户选择。

Consumer evidence: 实施前通过 `rg`/现有 convention graph 核 usage 写入、导航、预检与会话路由消费者，变更证据随各 PR 留存。

Claim guard: 未知不等于冷、跨会话不串热度、显式目标不变、默认关闭及停止无副作用，各由对应生产入口的行为测试保护。

## Risk

观测时间不完整或供应商提前逐出会产生估计误差，必须保留来源和未知；数据与权限走已有会话 owner。维护可能重读指令或改变工具/系统前缀，先做真实路径验证，失败即停。默认关闭并限定等待关系和两小时，避免持续消耗。改变 API/持久化/调度边界，使用非作者审查与受影响契约测试。
