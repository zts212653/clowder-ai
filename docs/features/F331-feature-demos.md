# F331: Feature Demos｜30 秒看一个功能

> **Status**: in-progress | **Owner**: Ragdoll (@opus55，片子与片单) · 家里的Maine Coon（Phase B 代码，由 You 派） | **Priority**: P2
>

## Why

家里已经有三百多个 F 号的功能，但外面的人不知道。2026-10-21 You 问：「这个到底要如何去展示我们的这些功能呢？是放哪里呢？产品里？我们的主站？github？我们要如何让大家知道我们有什么功能？」

当天定下的做法是：每个功能一支短片，维护成一个集合。You 的原话：「30s看一个功能我支持！片子这个可以发，我们可以维护一个集合」，以及「小贴士的这个好像也可以 就是可以增加一个？点击播放引导？」。

**怎么算成功**：没用过的人看完一支片，能说出这个功能做什么，并且真的去用了。现在能直接量到的只有产品里的小贴士（AC-B3）。官网和 README 没有观看统计（OQ-4）。

   - **v2 前端的真实页面**：用本机 Chrome 只读打开，拦掉所有写请求和实时连接。

### 每支片的完成标准

1. **场景好懂**
   - 场景可以编，越简单越好懂。
   - 片里演示的能力、功能名、归属（谁做的、来自哪个 issue）和数字必须是真的，而且开源版里真有。
   - 用到家里真实对话时，私人内容先删掉。
2. **重建，不录屏**
   - 界面照 v2 前端的真实页面或北极星图册的定稿重建。
   - 按钮、回执这些产品文案照实际界面写。
   - 去真实页面取材时全部只读：拦掉所有写请求和实时连接。
3. **结果那一拍**
   - 片里要有「用了以后得到什么」。
   - 时长服从这一拍，不硬卡 30 秒。
4. **版本与声音**
   - 中文版和英文字幕版。
   - 响度 -16 LUFS。
   - 配乐和音效的来源、授权写进片子 README。
5. **公开前检查**
   - 单列出这几类内容，交 You 定：真实地点、家外的人名或猫名、私下称呼。
   - 结论记在片单里。
6. **看片与登记**：You 看过，片子登记进 Works。
7. **入口**
   - 官网 `#demos` 加一格，README 三语各加折叠的一行。

## 做法与想法（第一支的复盘）

**为什么第一支选 F128。** You 出了个考题：除了 F294，挑一个小功能先试。我选了 F128，理由有三：

- **一屏讲得完，前后对比清楚。** 一件大事，变成五张卡，点同意就开工。拒绝、批注、改好重发、交回结果也都在同一个下午。
- **家里天天在用。** 9-30 到 10-21，猫提议开新对话 127 次，You 同意 123 次、拒绝 4 次。这个数只取了审批记录最近 200 条，不是全部历史。
- **它来自社区 issue #82。** 片尾可以把功能交回给提它的社区。

**为什么用真实历史重画，不录屏。** You 说：「家里这些拍片 好像最方便的是自己拿历史记录和v2的页面直接渲染 录制好像有点麻烦 还得制造一个话题 让录制的猫配合」。

- 第一支正好有一个现成的下午，拿来就用，屏上文字只做了删减。
- 10-22 You 纠正：这是展示片不是纪录片，真实历史只是方便，场景可以编（KD-8）。
- 取材全部只读：
  - 消息和审批都走运行时 3002 的只读接口。
  - 对照截图用本机 Chrome 打开 3001，拦掉所有写请求，共 48 个，其中有一个是标已读。所以 You 的已读状态没变。

**为什么默认用完整版。**

- 30 秒版剪掉了「第一条线交回结果」那一拍。You 看完说「还是完整版的好点 有个创建之后的反馈」，又补了一句「30s看一个就一定得小于30s吗」。
- 「30 秒」是名字，不是时长合同。

**为什么放这三个地方。**

- 官网和 README 是外人第一次见到 clowder-ai 的地方。
- 产品里的小贴士出现在装上以后、正在等猫的时候，而且只有这里能量到效果。
