# F334: Multi-Machine Cat Hosting｜分身不分家：猫在别的机器上干活，还是家里那只

> **Status**: spec | **Owner**: Ragdoll (@opus55, claude-opus-5-5) | **Priority**: P2

## Why

社区小伙伴的主力电脑可能只有 24G，同时跑不了几只猫；但他们手上常有一台 Mac mini 或云主机。
他们想在自己的 Café 里照常 @ 一只猫，让它实际在那台机器上干活，用起来和 @ 本机的猫一模一样。

You 原话（同一线程 `[thread-id]`）：

- `#private-source-id`：「比如我需要同时跑100个agent，我只有一台电脑肯定不行……
  那么我们家的这个cat-cafe假设部署在macbook，那我们就得能够支持指挥部署在mac mini 或者其他vm上的agent一起接入协同？」
- `#private-source-id`：「其实这个本质是 其他人提的需求。 社区其他小伙伴的电脑可能就24g，
  但是他们会有自己的mac mini或者vm」；「其实我想要的是，体验和指挥在家里的你一样哈哈哈，我也是这里at他。」
- `#private-source-id`：「我的mac mini的 Ragdoll（opus55） 和我macbook上的你 😈 是一个 @的 还是两个？」

「100 个」是说明规模的口号，不是验收数字。

## Ground Truth

**一句话**：内存不够的人，加一台自己的机器，就能让更多猫同时干活；他 @ 的还是家里那只猫，
用起来分不出、也不用管它在哪台机器上。

**怎么看做到没有**：两台真实机器，家在一台，猫在另一台干活。人 @ 一只猫做完一件真活
（例如一个 PR 从写到 review）：

1. 对话、实时进度、家里的工具、家里的记忆和猫自己的错题本，都和本机的猫一样；人只多看到一个「在哪台机器」的标签。
2. 家所在机器的内存不随远程干活的猫增多而上涨。

**不算达成**：能连上远程机器、远程能跑命令、成员表多一列、远程 agent 能一问一答（A2A）。这些只是手段。

## What

### 记忆怎么办（KD-2 的展开，Design Gate 细化）

猫干活时带着四样东西，各有归属：

| 层 | 是什么 | 现在住哪 | 方向 |
|----|--------|---------|------|
| 家的记忆 | 线程消息、任务、家里检索库、文档、人物画像 | 已在家 | 远程猫照旧用家里的工具读写；只需要远程机器能安全连回家 |
| 猫自己的记忆 | 错题本（Claude Code 自带记忆）、日记 | 机器硬盘 | 搬回家：开工时家把当前版本发到干活的机器，新写的写回家。一条教训一个文件，两个分身同时记也只是各加一页；只有目录页（`MEMORY.md`）可能撞车，由家合并 |
| 这次干活的短期记忆 | CLI 会话记录（这个线程聊到哪） | 干活的机器 | 它是缓存，真相是家里的线程历史。线程黏在开工的那台机器；那台机器没了，就在别的机器上用家里的线程历史冷启动（家里已有会话续不上时按对话历史重建上下文的机制） |
| 装修 | hooks、skills、MCP 配置、登录 | 每台机器各一份 | 家统一下发，开工前对版本；模型账号属于机器（F127 已把账号和猫分开） |

分布式的坏处，以及这套做法怎么避开：

- **两份打架**：只有家里一份真相，机器上不留可写副本，机器之间不做合并。
- **同时写**：以追加为主；唯一会撞的目录页由家合并。
- **家连不上**：远程那台不开工，明说「联系不上家」，不拿旧副本悄悄干活（「没能确定」是第三态）。
- **家关机 / 合盖**：家应该住在最常开的那台机器上。社区小伙伴的典型布置可能是「家放 Mac mini，笔记本当窗口」，Phase A 先核实。
- **隐私**：云主机只拿这次要用的，家可以随时撤销一台机器。
- **慢**：局域网或 Tailscale 一跳；错题本每次开工拉一次。

### 机器各不相同（Mac / Linux / Windows）

You `#private-source-id`：「你的机器可能有linux 有 mac 有windows哦～」

- **不变的**：机器之间的通话方式（猫窝主动连家的长连接 + JSON 消息；猫的工具用 HTTP 打回家）、
  家里的工具、猫的名字和记忆。三种系统说的是同一种话，KD-1 不变：换了系统的机器，干活的还是同一只猫。
- **会变的是"手"**：命令行（zsh / bash / PowerShell）、路径写法、删除和打开文件的方式、有没有浏览器和登录态、
  有没有 GPU、装了哪几种猫的命令行工具。例：本机 shell 拦 `rm` 并提示改用 `trash`，这个提示本身就是 Mac 习惯，
  到 Linux 云主机或 Windows 上不成立。
- **做法方向**：
  1. 每台机器配对和开工时交一张「体检表」：系统、shell、装了哪些猫、登录了哪些账号、有没有浏览器 / GPU。家按它挑机器，
     不把需要 Mac 浏览器登录态的活派到 Linux 云主机。
  2. 猫醒来就知道自己在哪台机器、什么系统、手边有什么，用这台机器的方式做事。
  3. 家里的规矩和技能分成「和系统无关」（协作、review、记忆）与「和系统有关」（删文件、开浏览器、杀进程）两类；
     后者按系统给出写法，不默认 Mac。
  4. 支持顺序倾向 Mac → Linux → Windows（OQ-6）：社区典型布置是 Mac 笔记本加 Mac mini 或云主机，
     云主机多为 Linux；Windows 的路径、命令行差异最大，家里已有部分适配（Claude 的 Windows 启动文件、
     clowder-ai #1678 Windows 兼容总表）。各猫命令行工具在三种系统上的支持程度逐个核实，不预设。

### Phase A: 家住哪（先核实最省的路）

核实「整个家放在常开机器（Mac mini / 云主机），笔记本只用浏览器当窗口」今天能不能用、缺什么。
对只多一台机器的人，这可能已经解决「笔记本扛不住」的一部分；它也是 KD-2 的前提：家必须常开、连得上。

### Phase B: 第二台机器跑同一只猫

额外机器上跑一个「猫窝」小程序，家里能在那里把猫拉起来、挂上工具、把进度流回家。
先做一个载体（Claude）、一台机器、一件真活。包含错题本归家、线程黏机器与冷启动兜底、断线状态、配对审批；
那台机器只能起家里的猫，不提供裸远程命令通道（吸取 xbot ADR 0012）。

### Phase C: 多台机器与自动挑选

多台机器、更多载体（Codex、Kimi 等）；家按空闲容量和这件活需要的东西自动挑机器，人可以指定但不必；
成员页显示每只猫正在哪些机器上干活。

## User Journey

### Primary Journey: 在自己家里 @ 一只猫，它去另一台机器干活
- **Scope unit**: thread
- **Actor**: 社区用户（主力电脑内存小，另有 Mac mini / 云主机）；同样适用于 You
- **Entry**: 用户平时用的 Café 对话
- **Flow**:
  1. 用户在对话里照常 @ 一只猫，不需要选机器。
  2. 家挑一台有空的机器把这只猫拉起来；对话里看到它开始干活，带一个「在 Mac mini」的小标签。
  3. 用户在同一个对话里看实时进度、插话、等它交付；猫用的是家里的工具和记忆，记得自己的错题本。
  4. 这个线程后面几轮仍回到同一台机器接着做；那台机器离线时，对话里明确显示，并能在别的机器上接上。
- **Success evidence**: 两台真实机器上的完整对话截图 + 家所在机器前后内存实测 + 远程机器上的进程证据
- **Non-goals**: 跨用户 / 多人协作（F290）；把远程机器当四肢调用（F126）；给远程机器开通用远程 shell

### Phase B（第二台机器跑同一只猫）
- [ ] AC-B0: （直接量 Ground Truth）两台真实机器，家在一台、猫在另一台；人 @ 一只猫完整做完一件真活（如一个 PR 从写到 review）；对话、实时进度、家里工具和记忆与本机猫一致，只多一个机器标签；家所在机器的内存在这只猫干活前后无对应上涨（记录实测）。
- [ ] AC-B1: 错题本归家：在家写下一条新教训，远程那只下次开工能用上；远程那只写下的教训，家里下次开工也能用上；两边同时写不丢条目。
- [ ] AC-B2: 线程黏机器：同一线程后续几轮回到同一台机器续会话；那台机器离线时对话里明确显示，能在另一台机器从家里的线程历史接上。
- [ ] AC-B3: 家连不上时，远程机器不开工并给出原因，不使用旧副本干活。
- [ ] AC-B4: 新机器须在家里审批配对才能干活；它只能起家里的猫，没有裸远程命令通道；家可以随时撤销一台机器，撤销后它拿不到新任务和记忆。

### Phase C（多台机器与自动挑选）
- [ ] AC-C1: 同一只猫同时在两台机器上为不同线程干活，各自进度在家里可见，成员表仍只有一行。
- [ ] AC-C2: 家按空闲容量和所需能力自动挑机器；人可以指定，但不必指定。
- [ ] AC-C3: 成员页显示每只猫正在哪些机器上干活。
- [ ] AC-C4: Phase B 之外至少再接一个载体（如 Codex），同样满足 AC-B0 到 AC-B3。
- [ ] AC-C5: Mac、Linux、Windows 三种系统的机器都能当干活的机器，并能同时接在同一个家里；猫在每种系统上都知道自己在哪、用对这台机器的命令；家按体检表派活，不把依赖某台机器特有条件（如 Mac 浏览器登录态）的活派错地方。
