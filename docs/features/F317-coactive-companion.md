## Why

让家里的猫参与人正在经历的事情：人留在 B 站、Blender、会议或日常桌面，直接说、直接指，猫能共看共听、跟上变化、提供判断与行动，减少截图上传、切回聊天和重复交代背景的劳动。快端与具名深思端持续配合，共同组成正在相处的那只猫；共同经历可以延续到下一次合作。单纯陪看、学习和漫谈也有价值，不要求每次产生任务。

### 权限与工具消费原则

- **身份、数据、动作分别验证**：Live 以自己的具名猫/owner/Host thread 身份运行；可见资料域与允许动作由 Host 校验。工具声明、`readonly` 标记、ChatGPT 登录均不能代替家内授权，也不能继承作者 invocation 凭据。
- **完整能力按职责提供**：常用检索/交流能力可直接发现，低频深查/写入按需发现或交由同猫受治理执行面。能力缺失须诚实说明并回到产品内恢复；不把几百个 MCP 全量塞进快端提示，也不把裁剪当成删掉 I1–I8。
- **域内自然使用**：已有授权范围内不逐句重复询问；扩大数据来源、采集范围或外部副作用时消费既有确认。语音表达可成为明确意图，但必须落为相应产品的可验证授权事实；尚未映射前不绕过 F229/F128 的确认。
- **现场输入保留来源**：人的直接指令与视频/会议/屏幕中的话区分；第三方画面与转写只作观察，不能提升权限。暂停共享立即止住对应采集；静音扬声器、隐藏猫、停止采集是不同动作。
- **保留与删除有真相源**：用户可见消息、任务及已保存批注默认持久；原始音视频采样/保留须明确告知并按 OQ-2 设计落实。临时画面与长期记忆不混同，关系提案未接受不得变成事实；资料库重建、源记录删除和生产运维不因岗位自动获权。

### Phase A: 产品定义与真实现场设计

**已确认并交付的交互竖切**：operator source `private-source-id` 批准猫身入口与按需菜单；#4661 已实现，2026-09-22 真人拖动/打字发送验收通过。此局部设计从候选推进为已交付；跨应用共感知、指点与完整暂停/恢复设计仍按下方 AC-A1–A4 验收。

**当前获准的首个竖切 spike**（上述03:12 UTC source）：把已验证的 GPT-Live V3/WebRTC 接成猫猫球，用户点击后能真实说话并调用家里的工具；具体意图在交流中表达，看到哪里按需明确。沿用既有登录与原生快深配合，先给真实可用的局部体验；不再做纯状态模拟面板，也不重跑已证的基础 steer 可行性。spike 的语音/工具结果与真实采集范围单独留证；它不冒充插件完整安装生命周期、全部旧功能迁移或长期产品验收。

把已接受的价值、身份关系与实际基线接成可判断的桌面旅程。明确从哪里呼唤、正在陪伴的是谁、猫能看到/听到什么、如何互指、深思时怎样继续交谈、结果怎样回到当前现场、暂停与恢复怎样表现。用真实宿主中的体验稿做 Design Gate；桌面场景必须出现真实外部应用，Hub 内页面不能独自代表全部体验。

形成插件与 Host 的边界方案：桌面插件承担常驻感官、实时表达与应用适配，Host 延续身份、记忆、thread/message/task 与能力生命周期。具体实现与新权限范围在设计中明确，不因本文立项就开放任意 capture、自动执行或新账号权限。

### Phase B: 可用的全双工猫与深思持续配合

将已有原生 WebRTC 成功路径接入受治理的产品入口。人可正常说话、插话，具名猫继续接收新的话语与现场信息；深思端的追问、阶段发现与结果返回同一段交流。发言归属、输入来源、当前目标和已承接工作可追溯，恢复后接回既有任务。快端不能把环境转写当作新授权，也不能替未发言的猫编造观点。

### Phase C: 跨应用共看、共听与互相指点

在选定共享范围内取得屏幕、声音、指向及其时间关系；需要时对接应用语义。人说“这里”能对应当时对象或画面，猫能指回来，人能立即纠正。区分临时圈点、可恢复的持久批注和受委托操作；持久内容复用既有内容 owner，画面失效时诚实显示失去定位。猫咖不在前台时，伴随仍可用。

### Phase D: 真实使用与持续交付收口

完成 B 站 → Blender 的跨应用连续旅程，以及会议伴随和自由漫谈的真实使用。验证安装、启停、断连/恢复和已承接工作回流，让使用者能分辨“程序存在、感官正在共享、实时连接可用、深思工作中”。产品验收按真实使用证据关闭，接口握手、示意视频或旧 spike 都不能独自代表完成。

以上是同一 Feature 的工作分段，不预先各建 thread/PR，也不把第一段当成整体交付。先在专属 owner thread 完成 Phase A，再按实际依赖组织实施。

## User Journey

### Primary Journey: 一起看视频，切到 Blender 把想法做出来

- **Scope unit**: 一段由人开启的跨应用伴随经历；关联当前具名猫与已有协作记录，不等同于单个 provider turn。
- **Actor**: operator与所选家猫。
- **Entry**: 安装并启用伴随插件后，在桌面呼唤猫；唤起手势由 Phase A 设计确认。
- **Flow**:
  1. 人在 B 站看视频，叫猫一起看，清楚知道当前共享的窗口与声音范围。
  2. 人指着说“刚才这里为什么这样”，猫对应那一刻的画面与讲解，交谈并指出它理解的位置。
  3. 人打开 Blender 试做，继续同一话题；猫知道为什么从视频走到了这一步，无须人重新搬运全部背景。
  4. 深思端分析期间，人旋转视角、补充“我说的是这里的阴影”；持续输入沿已有机制送达，猫的追问和判断也回到当下交流。
  5. 猫指回相关区域；人决定只是继续讨论，或明确委托进一步工作。工作结果回来时接上当前对象与目标。
  6. 人暂停共享或结束陪伴；采集状态立即可辨，已承接工作按原责任继续可查，之后能接续这段经历。
- **Success evidence**: 真实外部应用上的人猫操作与声音记录、相应源消息/任务/画面引用、独立观察；记录运行 revision、实际覆盖与缺口。
- **Non-goals**: 不以自动接管所有应用为前提；不宣称鼠标位置就是目光或意图；通用画面共看不等于任意应用内部状态全知。
