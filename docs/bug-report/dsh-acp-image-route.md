# DSH ACP 图片能力与成员模型保持一致

## 目标与边界

通过自动检测添加 DSH 后，用户选定的视觉模型应能接收图片；切换模型和恢复会话时，连接能力应与实际启动路由一致。本次仅修改 Clowder 接入，不修改 DSH 源码、用户原生 profile 或凭据，不增加手工配置步骤。

实现基线：公开 `next` 的 `c80bde90c30d58d5c559e89bf738c58245f340c6`。

## 根因

DSH 在 `initialize` 时根据 ACP profile 的启动默认路由计算 `promptCapabilities.image`，并在连接内缓存。Clowder 原先在 `session/new` 或恢复之后才应用成员模型；如果启动默认路由不声明图片输入，切到视觉模型也无法解除连接级限制。

自动检测只能证明找到启动入口、profile 或模型选项。取得模型列表不意味着图片调用已验证。Clowder 的图片准入又早于会话配置，因此无法靠后续 `session/set_config_option` 修复这条连接。

## 方案与分工

- 砚砚负责托管启动补丁、Factory 接线和池代际回归；鲸鲸负责独立设计核对、模型探测链路及其回归。双方交叉审查对方代码。
- 复用已有的 DSH 托管补丁：将显式选择的原生 `[provider, model]` 写入 ACP 配置行，再建立连接。识别命名 DSH 启动器和有已安装包元数据的 Node DSH 入口；其他 ACP 保持原行为。
- 未显式选择模型时，保留 DSH 原生默认。探测所选模型的临时连接与实际执行采用同一启动准备过程。
- 补丁按完整内容寻址。模型变化导致参数及现有池签名变化，旧池按已有机制停止新准入并等待活动租约结束；新池重新握手，后续恢复原逻辑会话。
- 验证器重建完整模板并校验内容地址，拒绝额外 YAML、动态表达式或在同一路径偷偷换成另一条合法路由。

Architecture cell：现有 ACP provider / runtime catalog。Map delta：none。Why：没有新增存储、权限 owner、协议或用户入口；复用已有补丁和进程池生命周期。

## 生命周期与代价

成员模型仍以现有成员配置为准，补丁只投影该选择，不保存第二份可编辑模型配置。进程池仍拥有连接生命周期，DSH 仍拥有原生会话历史。显式模型变化需要一次冷启动；同一路由可以继续复用池。已有内容寻址补丁可并存，支持仍在结束的旧连接。取消、权限与通用 ACP 能力检查保持既有契约。

## 验证要求

1. 回归先验证旧代码缺少启动路由、缓存 Node 入口未处理；再验证修复后显式模型、继承默认、同模型复用和跨模型更换池。
2. 既有 secret guard 和 ACP 图片传输回归继续通过；篡改模板或路由不能绕过校验。
3. 使用真实 DSH、隔离 HOME/profile/session 和合成图片，验证默认文本路由为 `image:false`，选择视觉路由后为 `image:true`；真实模型识别只存在于图片像素中的随机码。
4. 切回文本路由时图片明确拒绝；再切视觉路由并恢复同一个 session，历史图片仍可读取。原生 profile 文件保持不变。
5. 模型探测验证显式模型在握手前生效；无模型、非 DSH、缺失/损坏 profile 保持原边界。

实际命令、结果及尚未通过的验收在 PR 的验证说明中记录。握手、fixture 和真实模型结果分别列出。

回退：回退本 PR 即恢复原启动链路；不需要迁移或删除会话数据。历史托管补丁不含凭据，不要求用户改回原生配置。
