## 目标与结论

用户要求仔细分析 Issue #1466（包括评论），指出先前 12 阶段原型的遗漏，并重新制作原型。关键修正是：

1. Issue #1466 的首启流程是“看懂团队示范 → 配置自己的伙伴 → 第一次真实交流”，并不是 12 个强制教学步骤。
2. 三猫协作、自动打字、`@`、审查后改进属于可确定重放的脚本演示。真实模型很难稳定控制这些镜头时，应采用明确标注的 mock 数据，不能把它伪装成生产调用。
3. 客户端探测、登录完成、用户勾选和成员生成属于真实状态门禁或功能原型。点击“去登录”不等于已登录；未完成登录不能进入成员交接。
4. 进入真实主窗口后，用户应能自由聊天。F155 入口提示是非阻塞提醒，不能挡在第一句话之前，也不能把自由聊天的消息当作阶段推进信号。
5. 训练营阶段 8–12 属于可选、可观察的后续协作旅程。每一阶段必须出现具体产物或状态变化，不能靠“继续”按钮空跳。

上一版 [bootcamp-onboarding-prototype.html](../../design/bootcamp-onboarding-prototype.html) 把 12 个阶段都做成强制线性步骤，且自动演示、多猫审查改稿、client 交接与阶段 8–12 的具体产物均不完整。该版本保留为历史材料，不再作为 Issue #1466 的验收原型。

新稿位于 [bootcamp-onboarding-prototype-v2.html](../../design/bootcamp-onboarding-prototype-v2.html)。本次完成后应在下面填写实际浏览器验证结果和 commit SHA；在验证前不声称交付完成。

## 旅程边界与状态

| 区段 | 类型 | 可推进依据 | 完成后发生什么 |
|---|---|---|---|
| 1–4：开场、自动打字、两猫 `@`、审查改稿 | 确定脚本 mock | 脚本事件完成；播放、暂停和回看仅控制演示 | 让用户看见“团队合作使结果更好” |
| 5：解说收束 | 脚本中的用户确认点 | 用户选择进入设置 | 清楚说明刚才是示范 |
| 6：client 清单 | 真实状态边界；本原型用 fixture | 至少一个已安装且登录完成的 client 被选择 | 绑定成员；pending 不可越过 |
| 7：团队交接 | 原型交互 | 已选择成员且交接视图可见 | 解说猫成为真实前台猫；其余示范猫不进真实成员列表 |
| 8：第一次真实交流 | 自由聊天；当前原型为功能 mock | 用户自行输入并发送；mock 回复只用于表现 UI | 非阻塞地提醒成员/密钥入口；不自动进入 bootcamp |
| 可选训练阶段 8–12 | 独立的协作演示路径，所有 Agent/文件状态为 mock | 每幕显示任务产物、审查状态或交付结果 | 展示需求、设计、开发、多 Agent 审查、验收交付 |

“训练阶段 8–12”与“Issue #1466 八幕首启”是两套不同概念。界面中必须把它们分开命名，避免数字相同造成误解。训练阶段 1–7 是否应作为强制范围，当前没有足够依据，必须回到完整 issue/用户目标评审后决定；不能默认把 12 幕都强制化。

## v2 验收清单

### 首启脚本演示

- [ ] 有清楚、常驻的“原型 / mock 数据 / 不调用真实模型”标记。
- [ ] 三猫开场由用户开始；演示播放、暂停、重播、回看行为可操作。
- [ ] 输入框逐字自动打出一条具体请求，打字完成后才出现脚本发送状态。
- [ ] 画面明确出现 `@` 缅因猫、猫加入气泡、审查意见和修订结果。
- [ ] 初稿与终稿差异可见，用户能理解同一结果因协作变好。
- [ ] 解说明确说明刚才是示范，下一步将配置用户自己的伙伴。

### 配置与交接

- [ ] 0 client：不允许继续，显示安装/登录提示和重新检测。
- [ ] 1 个已登录 client：只生成一个真实成员，交接文案准确。
- [ ] 多 client：按选择生成成员，未选择或未登录的 client 不冒充成员。
- [ ] 去登录必须保持 pending，只有模拟外部登录完成事件才允许选择。
- [ ] 交接后清楚区分示范团队和真实团队；前台猫身份延续。
- [ ] 刷新后回到未完成状态，不重放已完成示范；首次对话消息保留。

### 自由聊天与可选 8–12

- [ ] 真实主界面先可见，F155 提醒位于非阻塞区域，不遮挡聊天记录或输入框。
- [ ] 用户可以发送任意自由文本；是否发送 `@opus` 不应自动令训练阶段跳跃。
- [ ] 可选训练路径不会成为首次对话前置门禁。
- [ ] 阶段 8 生成结构化需求卡（背景、目标、范围、验收）。
- [ ] 阶段 9 展示有内容的设计方案，并有明确确认状态。
- [ ] 阶段 10 展示 mock 文件/预览/运行状态和完成证据。
- [ ] 阶段 11 展示主猫 `@` 审查猫、审查意见、修订和处理状态。
- [ ] 阶段 12 展示验收清单、交付结果和协作回顾。
- [ ] 每项 mock Agent 行为和 mock 文件均有标注；没有伪造真实模型或本地执行 claim。
