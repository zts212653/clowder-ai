## 已验证行为

- 原生工具目录与成员身份分开：内网默认只有 CodeAgent、Claude Code、Codex、DSH、Pi；CodeAgent 一个工具对应三套独立推荐角色。未知/已有插件绑定仍保留在原高级入口，不按程序名合并授权。
- 切换/恢复草稿、检测失败重试、客户端缺失与重装不覆盖已有参数、模型、角色 ID 或创建回执。
- “小鲸鱼 · 鲸鲸”在 @ 候选、插入文本、已发消息和回复头一致；保留内部 `dsh` ID、旧 `@dsh` 原始历史与路由。重名、注册别名/人类别名前缀、分组关键字和 Unicode 边界冲突均有回归；A2A 别名规则不扩大。
- DSH 从已有 profile 读取自定义供应商，明确确认后生成成员专用 patch；命令、模型/思考强度、账号、授权或工具变化使旧回执与晚到响应失效。前端草稿不会成为任意命令探测入口。
- ACP 的 Windows 子进程显式隐藏窗口；插件、CodeAgent、DSH 的命令、参数、目录、环境、管道及权限不变。开发监督器和作者测试也显式隐藏子进程。

## CI、安装与仍待完成

新增 native TS、DSH UI、shared/人类提及和 ACP 隐窗测试已接入 CI，保留原门禁。旧的公共包名断言与无关受保护进程读取两个根因已修；第一次新 CI 又指出 main 超 350 行，已用等价整理修复并独立核对。

Windows runner 另复现安装停止时序问题：`Stop-Process` 发出终止请求后立即枚举，目标可能尚未完全退出，从而误报失败。已增加确定性反例，停止后对同一批已核验归属的 Process 对象执行有界等待，再重新枚举确认；超时仍存活及不可读取的候选继续失败，不扩大停止权限。远端最终结果以 PR 为准，不以定向测试替代完整 CI。

本机 `pnpm check` 在未修改的 F290 路径分隔符断言处失败；直接全仓 Biome 还遇到既有 Windows CRLF 换行差异。上述不计入通过范围，没有为此批量改写仓库或关闭门禁。

旧扩展 Windows 矩阵的严格祖先夹具、media-ledger fsync/AGY 路径权限及 Unix 专用测试缺口仍未在本轮闭合，不宣称这些能力完整验收。此前 `3d1d78994` 安装包的 EXE 首装/升级证据仅属于旧包。

`4523e85da` 已补齐全部七类递归负载与数据根的双向重叠拒绝，以及升级前校验和卸载前只读门禁；包括 `bundled` 和 materialized shared refs。定向回归 57/57、原样生产 include/helper 的独立原生 Inno 门禁 5/5 通过；完整交付 EXE 的安装和历史保留仍以该包单独回执为准。旧卸载器不会自动获得保护，不能先卸旧包来解决多版本混用。默认外置根的同目录升级方式及多包盘点步骤见 [内网使用说明](./intranet-windows-codeagent.md#已安装过多个测试包时怎样更新)。

Windows runner 的新只读测试曾额外重传 `InstanceRoot`，8.3 路径拼写与 PowerShell 展开结果不同导致冲突；测试现按生产卸载器仅传 `AppDir` 与 `ValidateOnly`。确定性短路径反例已复现，修正后仍检查 marker、历史字节及未创建默认目录；生产身份校验没有放宽。
