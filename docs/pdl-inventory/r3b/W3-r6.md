## 2. 看得见的变化

- 设置 → 账户：真实账户分组、使用成员、原生登录状态、备注/密钥/Token 编辑；Codex 登录开始、取消、确认、冲突另存；切换先读真实预览，展示受影响成员与例外，再带同一范围的 previewToken 提交。拒绝时保留预览/编辑弹窗。
- 设置 → 成员：正典绑定的成员头像不再出现普通上传；“正典头像”显示版本、取代理由，可选版本或上传，并要求理由。上传和选择都携带后端真实 revision；读取/切换成员不提交头像。成员切换期间的返回值按成员归属使用。
- 成员客户端配置和插件配置：clientLibraries 指向的 records 字段逐行出现“检查”；结果写回那一行的 VM，不自动运行、不保存配置。
- 设置 → 能力画像：按真实 modelGroups 展示成员画像、路由信号与人为观察；新增观察经 owner 保存后重读。
- 设置 → Skill/MCP：真实目录与正文、默认/项目范围、全局和按成员启停、标准/自定义挂载点、MCP 连接表单与工具探测、安装预览/确认、删除外部 MCP、系统发现、漂移检查和显式确认后的同步。已有秘密不以遮罩值写回；原值未改的已保存 MCP 探测由 owner 读取其配置。
- 设置 → 协作规则：真实生命周期清单、规则文件只读正文、注入片段编辑/清除 override/恢复备份、指定成员的编译预览。
- 对话菜单 → 对话设置：目标及同步状态、保存目标/重试同步、运行时账户与配额事实、可表达的 effort、Standard/Fast。写入目标是打开设置的那条对话，不借用当前活动对话 id。仍存在第 4 节列出的原型表达缺口。
- 接上已有会话：真实成员的本地会话列表、已绑定状态、手工 ID 检查；点击提交才调用已有 admission.importSession，拒绝时保留原选择与错误。
- 项目选择 → 浏览目录：真实目录、磁盘根、目录展开和新建子目录；点击“选择文件夹”才交给已有 newProject admission。目录行只给本轮有真实 owner 的“新建文件夹”动作，不绑定演示的全局目录改名/删除。

- 首页 → 协作演示：复用项目保留的 `demo-story.ts` 与 `demo-deliverable.ts`，同一个回放 owner 推进消息与预览阶段，重播从头开始；“下一步”进入已有 nativeSetup。演示演员使用独立 guide: 身份，不冒充已配置成员，不调用模型。

通知区本轮没有挂出；引导的自动入场/完成/关闭回执仍是原型缺。原因和精确落点见第 4 节。

## 4. 未完成、拿不准与需要协调的项

### 原型/产品契约缺口
