### svc：通用异步 setStatus 的缺口

原型与复制件相同，`engine/core.js:640` 的 doIt 调用：

```js
if (e.set) e.set(x, f, v, old);
// 随后直接返回撤销函数，未返回 / 等待 e.set 的 Promise。
```

`entChange` 本身在 `core.js:544` 支持 doIt 返回 Promise，`dialogSubmit` 在 `:707` 支持异步保留确认框；中间的 setStatus 没有传递该回执，真实操作尚未完成就关闭确认，拒绝会游离到框外。需要原型把异步状态写回的完成 / 拒绝接回这条通用链路，再复制新 tag。

这是 AGENTS §1 的复制层边界、§2 的通用机制与时机，不能在宿主针对 svc 另加一套 setStatus / 确认恢复。故本轮不登记 `MENU_FNS.svc`，也不只返回其中的修改项。真实卸载路由已核实；已有安装 / 修改对话框与 owner 保留，可在通用能力补齐后继续该项。

真实触发器：`theme/default/views-settings.js:206` 的 service 行 `acts`，when 为 installed 且非 running。当前仍显示菜单入口且 `menuItems('svc')` 为 0；未改复制主题。

### ruleAdd：原型演示，没有创建并登记的 owner

1. `P/app/settings.js:701–704` 只 push `SS().extraRules`，连真实文件都未写入。
