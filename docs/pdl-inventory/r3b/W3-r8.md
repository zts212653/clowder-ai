## 2. 看得见的变化与数据流

- 成员设置：真实 binding mode 为 override 的 Codex/Claude 账户字段提供原型的“跟随”动作；点击后草稿显示当前账户，保存前不写成员。已知 follow 状态显示跟随说明。
- Skill 的挂载对话框：每个单项开关实际使用 `capSkillMount {n,m}`，调用原能力 writer。
- 插件详情：安装先展示原确认框及插件带来的能力；提交期间显示安装中，后端确认后显示真实已安装状态；冲突/拒绝保留确认框与错误，插件仍未安装/未启用。
- 环境变量页：显示真实可编辑变量、分类数、敏感值配置状态；编辑仅提交该键，失败保留输入，后端确认后更新值及需要重启的提示。
- 真实引用的 HTTP(S) 链接通过同名动作交给宿主打开。组件目录的 PCF 样例没有进入生产应用。

新增数据遵循 `fff2d35dc8` 的流向：`useSettingsBindings.data` 保存原始 owner 回执 → 既有 `ProjectDataBinding.data` → `PdlAppHost` 的 action 完成发布 → 控制台 `receiveChatData` 复制并比较 → VM/动作消费 held 副本。`VM.env()` 不调用 `api.get`、`chatPort.models` 或 hook 的 model builder；宿主原对象后续被修改，也要等下一次 push 才改变 VM。没有新写一套接收或 diff 机制。
