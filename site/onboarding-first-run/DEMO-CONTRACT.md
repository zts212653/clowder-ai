# 首次启动用户旅程 — Demo Contract

> 本目录是 #1466 的**设计原型**：说清思路、原型与流程，交给实现者参考。
> 它不是产品代码，不接真实模型，不读本机任何文件。

## 0. 一句话契约

- **Demo 名称**：Clowder AI 首次启动旅程原型
- **demo_kind**：`journey_validation`
- **目标观众**：先是 operator（体验并定稿流程），再是上游实现 #1466 的伙伴（照着它实现）
- **使用场景**：operator 自助点击体验 → 内部对齐 → 作为 issue 参考附件
- **观众复述句**：我看到三只猫先演示了"说一句话，团队分工并把结果改好"，然后刚才解说的那只猫变成了我自己的第一位伙伴，因为配置步骤按我电脑上真实可用的客户端给我配了成员，我接着就说出了第一句话。
- **希望观众接下来做**：operator 定下第 8 幕放在开口前还是开口后；实现者按 Journey ledger 的状态与门禁实现
- **主 claim**：新用户可以不填任何 key，从首次打开走到第一次真实对话，并且演示承诺的效果和他真正拿到的东西之间没有断层。
- **非目标**：
  - 不证明客户端探测、登录态判断、模型回复在真实环境可行（那是 #1463 与实现阶段的事）
  - 不定稿视觉细节、文案措辞、猫的动画素材
  - 不设计安装包 DMG、图标（#1466 已说明单独设计）

## 2. 视角与主角

- **视角**：工作台（新用户第一次打开）
- **主角**：新用户
- **受益者**：新用户
- **操作者**：新用户（开发控制条仅供讲解者模拟外部条件）
- **规约 owner**：operator（定流程）
- **裁判**：operator 亲手点完；实现后以真实首启数据为准

## 3. 信号路径

```text
用户点「开始」 → 演示脚本播放（固定） → 解说收束 → 本机探测结果（真实环境由 #1463 提供；原型为 fixture）
→ 用户勾选 + 各 client 自身登录结果 → 生成成员 → 解说猫交接为第一位伙伴（交给 F229 前台猫）
→ 用户第一句话 → 真实模型回复（原型为占位回复）
```

| 检查 | 答案 |
|---|---|
| 系统实际看得见什么？ | 本机 CLI 是否安装、是否已登录（只判断有无）；用户勾选；用户输入 |
| 哪些信息它看不见？ | 凭证内容（不读、不传前端）；用户对 CLI 的偏好 |
| 是否存在只负责转发的 middle man？ | 无。演示脚本不经过任何模型 |
| 反馈冲突时谁决定？ | 用户勾选为准；探测结果只决定"可选"与否 |
| 哪类信号必须拒绝？ | 用户点了"去登录"但登录并未成功 → 不能算已登录，不能进入下一步 |

## 5. 灵魂画面

- **无旁白也能表达的变化**：演示里负责解说的那只猫，出现在用户自己的主窗口里，头像旁是它绑定的客户端名称，输入框里是用户刚打下的第一句话。
- **画面前**：示范对话（三只猫）已收起
- **画面后**：用户自己的对话，只有这只猫（单客户端时）
- **观众看到后应说**："刚才那只猫，现在是我的了。"
- **必须保留的真实细节**：客户端名称来自第 6 幕的真实勾选；没有被配置的示范猫不出现在成员里。

## 6. 场景表与 Journey ledger

| # | 幕名 | 世界状态变化 | 屏幕主画面 | 进入下一幕的门禁 | 自动验证 |
|---:|---|---|---|---|---|
| 1 | 开场 | 认识三只猫 | 暗场，三只猫跑出来 → 定住后随机闲置 | 用户点「开始」 | 场景顺序；闲置动作不重复卡死 |
| 2 | 示范开始 | 知道在哪里说话 | 猫退到两侧，主窗口出现，输入框自动打字并发送 | 脚本（打字完成） | 脚本推进受暂停控制 |
| 3 | 第一只猫接住 | 猫 = 成员 | 布偶跑向气泡、缩进头像，写出初稿并 @缅因 | 脚本 | 头像与气泡同一只猫 |
| 4 | 同伴让结果变好 | 团队的价值 | 缅因入场指出一句新人看不懂的术语；布偶改好，改动处高亮 | 脚本 | 终稿与初稿确有差异 |
| 5 | 解说收束 | 我们是干嘛的；刚才是示范 | 暹罗解说："你说目标，我们自己分工……刚才是示范" | 用户点「下一步」 | — |
| 6 | 召集你的团队 | 我的团队从哪来 | 本机客户端清单（按 fixture：0 / 1 已登录 / 1 未登录 / 多个） | 至少勾选 1 个**已登录**客户端 | 未登录时下一步禁用；零客户端停在安装指引 |
| 7 | 交接 | 示范团队 → 我的猫 | "从这里开始，是你自己的猫"；解说猫成为第一位伙伴，未配置的示范猫退场 | 自动（交接动画完成） | 成员数 = 勾选的已登录客户端数 |
| 8 | 第一次真实交流 | 真的有一只猫在和我说话 | 真实主窗口；Rail 默认钉「成员」「密钥」；输入框预填可编辑建议；右下角一条入口提醒 | 用户发送第一句话 | 陌生 sentinel 输入后出现在对话中；提醒不拦截发送 |
| 8′ | 入口提醒 | 之后去哪里加东西 | 进入主界面即出现一条轻提醒；点「带我看看」才聚焦「成员」「密钥」 | 无门禁——**不挡在第一句话前面** | 提醒在到达时可见；看过即不再出现 |
| — | 终态 | 旅程完成 | `firstExchange = done` | — | 终态可判定 |

### Journey ledger

| # | actor | 起始状态 | 用户动作 / 系统信号 | 状态迁移 | surface | 下一状态 | 失败 / 恢复 | 验证证据 |

| 1 | 用户 | `stage=intro` | 点「开始」 | `demo=playing` | 开场舞台 | 示范对话 | 刷新：回到开场（示范未看完不跳过） | journey test |

## 8. 视觉语言

- **复用的产品结构 / token**：见 §1 visual_source_of_truth；色值抄自 `theme-tokens.css` / `console-tokens.css`
- **角色素材**：canon `sit / run / walk / wave / think / groom / look-up / yawn / stretch / tail-up / loaf`
- **入口提醒的实现**：原型自带一个两步聚焦只为演示节奏；**实现时应复用 F155 场景引导引擎**（`guides/flows/`），不新建第二套引导系统
- **需要新画的**：无。奔跑用现有单帧 `run` 与 `sit` 交替近似，**正式实现需补跑步循环**（已在 #1466 说明）
- **不能使用**：emoji 当 UI 图标；卡片四周加框；满宽主按钮；UI 上出现 F 号
