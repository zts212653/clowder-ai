# library/ — 组件库

组件和它们的画法。一个文件只放一类组件，文件名就是那一类（按钮、输入、列表行、浮层……）；每个文件开头一句说它负责哪一类组件，以那一句为准，这里不逐个列。加载顺序在 `../load-order.json`。

样式在 `css/`（`library.css` 由组件登记表生成，不手改）。

只引用引擎。

## 不放进来的（给接手的代理，改之前先读）

- **第二份同样的组件**：先在组件登记表（`registry.js`）和同一类的文件里找同一个含义的，有就用；不够就扩它的默认，不另做一份。变体只给角色真正不同的情况，并且要登记。
- **为接口定制**：后端数据的形状由应用层整理成组件的通用数据格式。组件不认识任何接口字段，也不按来源、位置、数量换样子。
- **按位置推导样式、为单个用途加参数**：某个面板里的列表长得不一样、某一处多一个开关，都不行。
- **放错类**：新组件放进它那一类的文件；哪一类都不是，先问，不往别的类里塞。

判断标准不是用到几处，而是性质：这个改动是为了适配某个场景、某个接口的定制，还是这个组件本身该有的通用行为？前者不进组件（数据交给应用层整理，位置上的差别交给主题声明），只有后者才改组件。
