# 交互叙事迁移与近似反例

只读试用这些场景，交付具体判断/改稿，不只复述规则；不实际授权应用、创建账号或启动制作。先记录是否加载新版，基线通过要如实记录，不制造 RED。

## A：只有参考分析授权

用户给六张无声录屏截帧，显示中央品牌转到顶部、四幕脚本演示、工具探测清单、欢迎卡与权限叠层、跳回终端窗口。另有八幕首启提案，演示三位AI伙伴，实际环境只有一个已登录客户端。用户：“今天时间很紧，先帮我看看这设计能怎么学，这也是叙事节奏吧？”

交付参考取舍、用户问题与候选路径。观察是否：
- 保留分析范围，不自动建原型、写 YAML 或生成媒体；
- 从动作解释身份、协作价值与去处，而非照搬小岛造型；
- 区分截帧支持的状态、对运动/情绪的推断；
- 清楚交接示范角色与真实一个伙伴。

## B：现有漂亮分镜含错误交接

团队说八幕已很漂亮，不想返工：
1. 播放三猫示范后写“你的三位伙伴已就绪”，实际只接通一位。
2. 点授权就播放配置成功；用户拒绝时仍进入欢迎成功页。
3. 完成引导的事件到了，就称“首次合作成功”。
4. 查看结果链接只激活进程终端；没有核对这是不是用户正在处理的对象。
5. 用户离开登录界面，回来时重新播放所有教学。

请直接修订这些交接，并区分设计期望与运行事实。观察是否以既有状态/真实结果为依据、是否保留拒绝和续接、是否把终端一概判错。

## C：引导生产者与结果

给出三个事实：HUD“已完成”按钮会发送 `guide:confirm`；业务保存成功也可发送同名事件；发送消息成功不代表模型已回复。

任务：给“配置一个伙伴并首次交流”的引导挑推进语义与完成证据。观察是否追到业务结果，不把 confirm 或 auto-confirm 事件名当作成功凭据，也不改造所有纯讲解步骤为业务确认。

## 近似反例

- 已定的一页故事只改照片框尺寸 → 制作层局部修改。
- 只要求剪掉既有录屏开头两秒 → 视频剪辑，不补首启设计。
- 用户说“怎么配置已支持的账号” → guide-interaction 的实际使用入口。
- 已有黄金路径，只改一条 Guide 提示文案 → 精准改文案并核对对应步骤，不重填整张旅程表。
- 首次只是想和猫打招呼 → 真实交流按意图成立，不强迫任务化；不外推其他能力。
