# 视频的声音稿、回听和时间轴（共享参考）

> 给 `video-forge`、`anime-forge` 共用。来源：《醋醋喵》EP0 制作复盘 `docs/videos/cucu-pr-flow/ep0-making-of.md`（第 2、12–17 条）、家里视频技能盘点 *(internal reference removed)*，以及 You 带回的漫画复盘 `docs/videos/zhuibushang-comic-retro/`。

## 1. 先给人看最便宜、又能下判断的那一样

> **「全片粗片用静帧、动效后期再补」只适用于画面要靠 AI 生成或画师画、重画很贵的片子**（anime-forge 那类）。Remotion 搭的片子也可以先给一句话、先做一段给他看，但那一段要按成片做：让角色动起来和让它平移费的工夫差不多，没有「先粗后精」可省。2026-10-14《AI-native builder 的一天》照这一节交了静帧平移的 5:38 全片粗片，动效、配乐都留到后面，交出去像半成品。

做动画和做 feature 一样贵。别等烧了大量 token、铺完全篇，才第一次给 You 看。给人看的东西从便宜到贵排：

| 关 | 做什么 | 给人看什么 | 回答什么 |
|---|---|---|---|
| 一句话 | 谁想要什么、为什么拿不到、用了什么办法、笑点或反转落在哪 | 几十秒读完的文字 | 这个故事值不值得拍？ |
| 最小样张 | 挑最可能毁掉整片的那一段（一个笑点、一次转折、一个关键动作），2–4 格画面配好音，拼成 10–20 秒的小粗片 | 看这一小段 | 好不好笑？看不看得懂？认不认得出角色？ |
| 全片粗片（动态分镜） | 草图或静帧按真实台词时长拼起来，加镜头运动 | 看一遍，报时间码 | 每格看不看得懂？哪里拖、哪里赶？ |

- 一句话在投入之前给他看。已经接受过的 brief 可以直接当这一句，不必再要他点头。
- **样张过之前，只为这一段花钱**：这段台词的合成与回听、这段的时间轴、这几格画面。全篇录音、全篇时间轴、铺草图和搭建，都等样张过了再做。
- 哪关没过，就只改这一关的东西，不往下铺。最小样张没过，只重做这一段。
- 图生视频、精绘、后期都放在全片粗片之后。动画短片按设定直接画正式风格的分镜图，不再单独精绘（见 anime-forge）。
- 最小样张的出处：漫画复盘里，先只画了四格动作试镜，You 看完认出了角色、被那一下打动，整篇的角色和关键动作就此定下。
- **静帧粗片可以用来验故事和节奏，不能当成片交付。** 这是两件事：前者是便宜的检查，后者是偷懒。

**声音稿是猫自己用的工具，不单独交给人听。** 最小样张只合成那一段的台词；样张过了，再把全篇旁白和台词合成一遍，查念对没有、量出每句真实秒数，给全片粗片排时间。TTS 念白是一部片子最平的样子，喜剧的节奏全靠表演和画面；拿它让 You 判断好不好笑，他答不出来，只会觉得烂（《尖头老鼠冤案》，2026-10-06）。

- 片子要靠台词讲故事（喜剧、内心戏、讲解）时，台词要进最小样张和粗片，不能删。EP0 第一次做成了无旁白的绘本，You 看完说「没剧情、没字幕、没解说，看不懂」。

## 2. 每句都回听

用 `../video-forge/scripts/tts-check.py` 录：每句合成后，本机 Whisper 听写一遍，和原文比对，对不上就换温度重录，最多三次；还对不上的标 CHK，交给人听。脚本退出码 0 只说明录完了，标 CHK 的句子仍要人听。

**两种合成方式，时间轴都只认最终那版。**
- 声音稿和多角色对白：逐句合成、逐句回听。坏一句只重录一句。
- 单一旁白的连续解说（产品片、讲解片的正式配音）：可以整篇一次合成，保住语气和呼吸。这一版要整段听写对一遍稿子（`tts-check.py --check-ref 整篇.wav "全文"` 也能用），再用强制对齐重新拿逐词时间。
- 不管哪种，时间轴只来自最终用进片子的那版音频。换了音频，就重新量时长或重新对齐，再跑一次 `timeline-check.py`。

- **参考音先核对文字。** 用 `tts-check.py --check-ref 参考音.wav "配的文字"`。参考音和它配的文字不是同一句时，模型会先念出那句文字，后面接一串胡言乱语。EP0 里旁白那条声线就是这样，16 句全坏。
- **同音词换说法。** 听写回来的词和原词不一样，常常是同音词，光听分不出来：寓言 / 预言、梳理 / 书里。换一个说法（「寓言故事」「故事大纲」），不要指望观众看字幕。
- **听写只当提醒，不当证据。** 同一句剪短后再听写，结果可能就变了（EP0 的「揉头 / 拭头」）。要下结论（比如放进 NG 花絮），先找人听。
- **猫判断不了好不好听，但能验这些：** 念对没有、同音词、胡言乱语、每段响度和峰值、说话时配乐压低了多少。
- **听写证明不了配乐没盖住人声。** 成片再听写一遍，只能提示哪句可能听不清。混音验收靠响度和压低量，再由人用耳机和外放各听一遍。

## 3. 时间轴只有一份

- 每句的时长从录好的音频里量（`takes.json`），镜头的长短跟着台词走：台词放不下就放长镜头，不要硬塞。
- 画面、字幕、配音、音效、配乐都读同一份时间轴 JSON；给人报时间码只从这份 JSON 里取，不要估。EP0 里估的三个时间码差了两三秒。
- 渲染前跑 `../video-forge/scripts/timeline-check.py`：两句话不许叠在一起，镜头之间不许有缝。跨镜头的长句最容易压到下一句上。

## 4. 声音设计的底线

- 对白优先。有人说话时配乐压低（EP0 压到四成五），说完再回来。
- 音效要么像，要么不放。代码合成的几十毫秒小音，很容易听成「唱片刮擦」「胶带声」；只放一听就懂、和画面动作同时发生的几声（门铃、盖章、点击），正式音效后期再做。
- 剧本里写了「音乐急刹」，就要先有音乐可刹。
- 声线是克隆来的，就只能私下看；要公开，先换声线，这由 You 定。
- 换声线时请 You 选：每个角色给两三个候选，各念同一句，选定再录。猫自己挑了预设声线就录整场，录出过方言相声（《尖头老鼠冤案》，2026-10-06）。

## 5. 往聊天里交片

- 聊天里发视频，文件上限大约 10MB。几分钟的片子要压到 960×540、10–12 帧/秒；大图版另外用 Finder 或工作区打开。
- 交片时附上：这一版改了什么、要他看哪里（时间码或镜号），还没做完的写清楚。

## 6. 审片时查音画（给审查的猫）

好不好看由 You 定；别的猫审片，查下面这些看得见、量得到的（这张表沿用 video-forge 旧版的 F1 审查表）。

| 级别 | 查什么 | 怎么算不过 |
|---|---|---|
| P1 | 话和画面对不上 | 说到 X 时，画面上不是 X |
| P1 | 字幕和声音错位 | 差超过 200 毫秒 |
| P1 | 声音断裂 | 段与段之间有不自然的静音或跳跃 |
| P1 | 对白重叠 | `timeline-check.py` 报重叠，或抽帧看到两层字幕 |
| P2 | 音量不均 | 原声、配音、配乐之间响度差太大；说话时配乐没压低 |
