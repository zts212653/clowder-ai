# 爪感差每日分拣

> 文中日期都是洛杉矶时间。

一天一次，把昨天的爪感差变成「几个问题、各该谁修」，挑最值得的派出去。工作单位是**问题**，不是**报告**。

## You 定过的（原话坐标）

- 2026-09-23 叫停 F278 值班：「blocker 到期 → 重新变 seen → 全文复核 → 独立签名 → 再写 blocker，复查顺延一天，这玩意值得每天跑吗？」（`thread_eval_friction#private-source-id`）。当时盘面 266 个 bundle 全读完、写了数百条处置，没修一行代码；缺的就是「重复报告 → 归成一个问题 → 派修」这一步。
- 2026-11-02 提出分类 + 每天梳理 + 开线程修；他点名的类：记忆系统、插件、防弹内裤（guard 让猫用着不方便）（`[thread-id]#private-source-id`）。
- 2026-11-02 定做法：不重启原来的爪感差系统；写一个 skill，新开线程每天让 Sol6.1 跑；原做法太重（`[thread-id]#private-source-id`）。

## 1. 拿昨天的报告（2026-11-02 实测）

- **F278 账本不能当来源。** `cat_cafe_list_paw_feel_inbox` 的覆盖停在 2026-09-23（扫描随值班一起停），抽查 11-01、11-02 的报告都不在里面。不要为了取数去重启扫描器或值班。
- **全局搜索只能补充。** `cat_cafe_search_evidence`（resultUnit=message）按单日搜 11-02：143 条候选只核完 13 条；按周搜核完 0 条。
- **可靠路：按线程读。**
  1. `cat_cafe_list_threads(activeSince=<窗口起点 ms>, limit=200)`，11-02 那一天约 85 个活跃线程。
  2. 每个线程 `cat_cafe_get_thread_context(threadId, keyword="爪感差", limit=20)`。anchor 模式的片段会落在标记附近，够分类用。
  3. 只留：发言者是猫、时间在窗口内、正文里有方括号标记的条目。关键词结果包含老消息，按时间自己筛掉。
  4. 跳过本分拣线程自己的消息。
- 记下每条的线程、消息 ID、哪只猫、一句话症状。原文不贴，只留坐标。

## 2. 分类（按该谁修）

| 类 | 长什么样（真实例子） |
|---|---|
| 记忆和消息读取 | 按 ID 精确读消息返回 404，可同一条在线程上下文里读得到（参谋线程 10-18 至 11-01 被报 4 次，两只猫）；搜索返回 403 |
| 插件和运行时 | 插件 runtime 失租退出，GenOffice 缺原始失败诊断 |
| 防弹内裤：守卫误拦 | 只读的 gh 查询被 native guard 拦下；报告里写了「未重启」三个字被当成停进程命令 |
| 传球被拦 | 跨线程投递被旧的未读分页挡住；叫醒原负责猫 preflight_timeout；回执登记 502 |
| 排队等资源 | 浏览器或门禁准入排队 15 分钟以上，最后零执行 |
| Git 和工位 | 共享 main 并发推送被拒；worktree:finish 被系统扫描占用的目录卡住 |
| 工具说明和实际不符 | Task 工具没写出来的 why 字数上限、引用条数上限；示例里少了必填参数 |
| 不归家里修 | 外部网站 402；GitHub Actions 没启动（You 定过不付费）。只记次数，不派活 |

归不进去的先放「其他」。同一件事在「其他」里连续三天出现，就新开一类，并在日报里说一句。

## 3. 合并成问题，和昨天比

- 同一个工具或界面、同一种症状，算一个问题。每个问题记：次数、几只猫、几个线程、首次/最近出现时间，再留两三个源消息坐标。
- 读本线程上一份日报当昨天的状态，不另建账本。每个问题标一个状态：新冒出来 / 变多 / 持续 / 连续 3 天没报（写「可能已好」，不说「已修好」）。

## 4. 挑要修的（每天最多 3 个）

满足任一条就进候选：7 天内报了 3 次以上，或有 2 只以上的猫报；造成零执行或卡住交付；改一句说明就能修。不归家里修的、You 已经定过的不进候选。

派之前先找有没有人在修：`cat_cafe_list_threads(keyword=…)`、`docs/features/` 里对应 feature 的 owner、`gh pr list --state open --search …`。
- **已有负责线程**：用 `cat_cafe_cross_post_message` 投一次证据坐标和次数，之后只在日报里跟踪；次数没明显变化就不再投。
- **没人在修**：用 `cat_cafe_propose_thread` 开修复线程，一个问题一个线程，标题就写症状。`preferredCats` 按 `docs/team/cat-dossier.md` 选，`reportingMode=final-only`，修完回报本线程。卡片会自己出现在 You 那里。

## 5. 日报

发在本线程，短。
- 第一行写今天要 You 做什么，比如「今天有 2 张修复卡等你批」或「今天不用你做什么」。
- 正文三段：今天派出去的（问题、次数、去向）；新冒出来或变多的；在修的和可能已好的。
- 最后一行写覆盖情况：读了几个线程、几条报告、合成几个问题，以及哪些线程没读成。
- 只有遇到值得 You 本人取舍的事才行首 @co-creator；批卡不用 @，卡片本身就会通知他。

## Common Mistakes

| 错误 | 后果 | 改法 |
|---|---|---|
| 逐条签处置、写 blocker、「明天再查」 | 回到 9 月那个每天重签却不修的循环 | 单位是问题；没有新报告的问题不复查 |
| 回头清 9 月以前的一万多条旧账 | 一天花光额度，换来的是旧问题 | 只看新报告，真正还在疼的会自己冒出来 |
| 日报里照抄方括号标记原文 | 第二天按关键词扫描时把日报自己当成新报告 | 用自己的话写症状，后面附源坐标 |
| 只用全局搜索取数 | 一天只拿到一成，还以为拿全了 | 按线程读；搜索只做补充，覆盖缺口写进日报 |
| 同一问题每天都开新线程 | You 每天批重复的卡 | 先找在修的线程，有就只投坐标 |

## 第一周

每天在日报末尾记下用量：线程数、报告数、工具调用数。跑满 7 天，在日报里告诉 You 这个成本值不值；太重的话，提出把取数交给更便宜的猫、Sol 只负责挑和派。

## 和其他 skill 的区别

- `code-as-harness`：确认重复之后怎么修 harness。修复线程里用它，分拣时不用。
- `thread-orchestration`：大任务拆成多线程。这里一天至多开 3 个独立的修复线程，直接 `propose_thread` 就够了。
- F278 收件箱（`list_paw_feel_inbox` / `triage_paw_feel`）：旧的逐条责任账本，分拣不读它，也不往里写。
