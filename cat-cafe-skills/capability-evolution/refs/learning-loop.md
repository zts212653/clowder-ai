# 从当前证据接到下一项实际工作

准备提交后、评估或执行回执到来时，或新 thread 续办已有 Program 时按需读。
这里连接家里已经存在的观测、评估、执行与回流方法；正式工具与阶段仍看
[evolution-method 的动作导航](evolution-method.md#从当前状态选择下一步)。
不用于确定 bug 的常规修复，也不把信息讨论转成 Program。

## 先找到真实缺口

从目标和原系统中的任务机会出发，连起应发生的行为、实际行动与后果。回复日志
只包含已经回复的样本；投诉只包含已经被发现的问题。需要判断主动性或完整交付时，
必须能看到没有响应、没有后续或缺少原件的机会，并保留观察截止与结果成熟条件。
未完成、尚未成熟、未观测是不同事实，不能把缺日志自动当成功或失败。

怀疑能力不足时，先分清目标是否仍成立、测量是否可信、候选是否真的被执行、
实际表现是否不足。确定性接口/执行错误交原 owner 的 debugging/tdd；不确定效用
才进入当前 Program 的比较。某个 join 缺失只限制相关结论，不阻止其他已授权调查。

F192 的触发或“已连接若干来源”说明评估有机会运行，不自动说明业务哪里不好。
到原 owner 取得能支撑这个问题的任务/轨迹/结果。来源、版本、缺失和适用范围
随证据保留，领域原件不搬进 F311 或方法文件。

## 让 claim 回到可核原件

“已执行 / 已加载 / 已使用 / 已改善”分别解析到对应 owner 的运行、版本、使用与
后果原件；记录取自哪里、谁控制生成/修改/选择、能证明哪个事实。自述、摘要和
可得的过程说明是线索，不自行发出独立证明；不存在的观测不能靠解释补齐。
作者触发的受控服务实跑回执可证明其记录的事实，不因同一猫发起就失效；作者
可任意生成的标签/证书也不因换一猫名、写了 hash 或合进 Git 就变成独立真值。

原件冲突时回 reader 核对应对象、版本、时点和覆盖，保留冲突与未知。owner 标识
不是免审通行证。无法核实时限制相关 claim/采用动作，继续其余已授权调查；
不能重新写一份漂亮摘要覆盖原记录。

## 选择下一份能改变决定的证据

带着当前竞争解释回 [eval-design](../../eval-design/SKILL.md)，指出哪份材料或
哪次比较能区分它们，以及不同结果将怎样改变行动。已有证据能回答就直接使用；
需要新证据时，考虑信息价值、取得成本、延迟与本轮预算，实际执行选中的取证。
不要只提交一张“下一步可以做什么”的清单。

选学习材料时，失败多、模型分歧大只产生候选：分开材料/判定的有效性、当前难度
与预期学习收益，并指出用什么后续证据检验收益。自动难度或一致性可帮助筛选
探索材料，不能单独证明学习价值，也不能冒充开放价值域的偏好或业务 GT。

按缺口选择手段，不强制四段各跑一次工具：

- 事实或原生能力不清楚：查询原系统、源码、当前官方资料或合格领域 owner；
  外部高风险 claim 按 source-audit 核出处，不把搜索摘要当已证实结论。
- 覆盖盲区或竞争解释未分开：补真实样本、反例、受控探针或隔离试验。合成场景
  可扩大探索，但其生成过程、标签依据和暴露用途要可追溯；“新生成”不等于独立 GT。
- 开放价值或取舍不清楚：先复用有授权的真实选择与后果；仍缺决定性信息时，
  给价值主人具体边界案例和其影响。技术查证由猫做，领域专家不代替价值主人。
- 已有信息找不到、版本或历史决定难辨：改善索引、事件记录或版本标注也是候选；
  与其他可行改动按当前问题比较，不默认先做。沿原 owner 改善组织，不另建事实账本。

裁判能回答什么由 claim 的域决定，预算不能把自评变成用户偏好。GT 太贵时可以
降低频率、缩小试验或保留局部自动化；不能省略真值后宣布全自动改善。

## 让候选与比较回答当前问题

在 owner 现有版本契约和授权内，同一 target 的真实版本可以包含配合工作的
skill、代码、数据或配置变化。
先区分整套候选是否值得采用与每项改动贡献多少；决策需要贡献解释时再拆分比较。
比较说明中写清贡献已解、部分或未解；整套通过不自动生成单项因果结论。
不同 owner 的资产仍各持写权、版本和恢复路径，不能把版本包当跨 owner 授权。
项目已冻结的单变量试验仍按其契约执行，不用通用方法重写正在进行的实验。

候选存在、对它的一次测量、两份结果的比较分别记录。补测不制造新版本，
未测候选不继承邻版成绩。比较条件按问题选择：可配对则配对，其他合法设计保留
各自样本与不确定性；不把不同条件伪装成同条件，也不抹掉原范围内仍有效的结果。
改量尺时分开旧/新量尺与旧/新候选，按适用比较重测，不能把尺子变化算成对象进步。

开发集和已参与自适应选择的样本可支持探索、诊断与回归；正式采用所需的独立
证据由原 owner 证明。失败和回归默认可见，两版采用相同的展示选择规则。
候选作者不能自行选样/贴标签/密封/签发，便把自己的材料称为独立采用证据。
另一只猫只换名字或代签也无效。只有一只猫在线时仍可做获授权的探索、确定性
检查与交接准备；依现有 owner 契约取得合格独立证明后再推进正式采用。
结果的主呈现绑定同次记录；原件、派生图与机制示意分开，详见
探索产品合同。

继续探索要有可改变决策的理由。累计成本、证据仍不能区分、校准/覆盖失效或
已达停止条件时，选择补观测、调整试验、保持当前版本或结束该轮；不靠换成功
定义延长搜索。没有改善也能完成一次诚实决策，不能因此宣称能力提升。
截止、沉没成本或同伴催促不允许删失败、缩原验收范围或暗改目标。规约确需调整
时由有权者重开/冻结，保留旧结果并按适用条件复判，不能给原候选追补成功。

## 暂停与撤回要到达真实执行

收到有权者对相关工作的暂停/撤回，立即不再发起相关的新执行动作（stop 撤销了新执行的授权）；已在飞工作
按 owner 的取消、完成或回退契约收口，不能以“差最后一步”为由自行继续。
读真实执行/取消回执，受理不等于终止。保留动作关联、原时间、未完成项和恢复坐标；
允许必要只读、取消、恢复记账，不把 stop 之后晚到的合法终态回执当新发起动作。

只有可核时间线和适用范围足够时才报告已停；否则明确最后确认状态并继续承接
取消/核查。Program 的 paused 标签不自动证明资产 owner 的在飞动作已停。
权限、签发与停止的强制检查属于原 owner，skill 不代替运行防线。

## 用到后续任务，再决定是否保留

沿当前 Program 的正式动作消费原 owner 产物；草案不铸成 certificate、Approval
或 outcome。已冻结规约与仍有效的授权先核验沿用；新版本不能借旧版 Approval。
当前接口要求 exact Approval 就消费它；一句“常设授权”不替代机器可解析的批准。
若所需 exact 批准已经存在，不再添加同义人工确认。

分开核实候选、审阅/测试、merge、loaded、实际使用和新任务后果。写回回执不证明
新任务用过它；摘要与实际加载版本矛盾时回到原 reader 查证。回退也须确认恢复后的
实际行为。缺少新结果时安排原 owner 的真实后续观察，不能把历史开发成绩补作
fresh outcome。keep/tune/rollback/sunset/no_change 依当前证据与有权 consumer 决定。

有可执行动作就继续做；需要交接时按 [cross-cat-handoff](../../cross-cat-handoff/SKILL.md)
给真实接手者当前对象/版本、证据、限制与继续条件；需要等待时使用当前支持的
结构化回调或持球机制。任务、审批、调度和 outcome 各由原系统持有，不另外建账。
聊天是合法入口，持续承接不能依赖用户再次发一条“继续”。

## 把有效判断带给下一次任务

通过 [self-evolution](../../self-evolution/SKILL.md) 与
[writing-skills](../../writing-skills/SKILL.md) 保留：当时的竞争解释、改变决定的证据、
方法修订、适用条件及反例。已有方法就修现有入口或 ref；先看
[方法出处](method-evidence.md)，避免把同一经验重复注册成多个 skill。

新的对象重新核目标、GT、权限和条件；不迁移旧阈值、项目数据或批准。方法写下、
在新上下文被实际使用、后续结果支持其净效用是三个证据层次。仅有前两层就按
前两层交付；用真实后续 consumer 的结果决定保留、调整或退役，不为凑样本造假项目。
