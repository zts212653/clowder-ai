# 跨对象进化方法：让下一只猫承接判断，而非重开讨论

在具体进化目标开始、已有 Program 续办或切换对象时读取。这里只保留 Clowder AI 的连接方法与真实易错边界；不替代领域调查，不复制领域数据，也不创造新的 Program、证据或审批契约。

准备之后需要选择取证、候选、后续使用或跨轮承接时，读[完整学习循环](learning-loop.md)；
需要理解或修订判断时，读[方法出处与证明范围](method-evidence.md)。后者保存本轮
共同思考的来源，不要求每个任务重复读史或另填账本。

## 先建立坐标，再决定改什么

从用户原话和已有 owner truth 回答四件事；已明确的直接沿用，只有真正的价值取舍才问用户：

1. **要变的对象**：哪项可变资产/行为由谁持有，当前版本是什么，能观察和改动哪些面？任务名称、业务目标与可变对象分别表达；相邻系统不因名称相近就被并成一个对象。对象或执行者在家外时，资产、权限与写回仍留在原 owner。
2. **想要的变化**：谁使用结果、谁决定值得不值得、允许牺牲什么？把愿望转成可证伪的 claim；不要挑已有实验恰好能通过的指标来改写愿望。具体目标可以先建立 Program identity，正式 Goal/测量/经济约定尚缺时保留 `constituting`。
3. **能获得的新证据**：哪条真实行为或后果能区分“变好了”和“只是分数涨了”？先核观测来源的适用范围；公开探索可以帮助发现问题，正式结论仍需按规约取得证据。由猫查询代码、资料和合格领域 owner，不能让用户替猫填技术表。
4. **本轮实际权限**：观察、准备候选、评估、生产写回和采用分别有什么依据？已有授权继续有效；能力可调用不等于 owner 授权，缺一类权限也不抹掉另一类已授权工作。

领域不熟时，先查对象的原生接口、真实行为、可变资产、测量来源和恢复方式。复用旧案例的提问方法，不照搬旧 owner、目标、模型/配置、阈值、角色任命或批准记录。对象边界发生实质变化时先对齐新的目标与 owner，不通过重命名旧 Program 偷换对象。

是否值得长期进化，看未来收益是否覆盖探索、验证、维护与失败成本。环境漂移、
GT 成本和可逆性影响迭代频率与自治范围，不是“缺一项就不能学习”的定义门槛；
GT 的判定域与取得成本分别核验，不能用便宜的裁判替代其射程外的真值。

## 从业务原话交出第一份准备

“专业地办好事、只在必要时请人介入”已经是可承接的业务起点。先保留原目标与待核查事实，展开多个可能相关的资产和条件；提示词、工作方法、协作、工具、数据、环境、模型或量尺都是按对象调查的候选，不是每个项目必须建设的清单，也不是已选定的干预。

第一份产物应让用户实际检查：我们理解的结果是什么、哪些对象值得查、怎样判好坏、判定依据从哪里取得、条件准备到了哪里，以及现状还不知道什么。需要定义“怎样判”时使用下节的 `eval-design`，带回本次适用的观察单位、估计量、反例、GT 域/来源与采集、裁判/付薪方、校准与证据限制；缺失事实保留为待核对，不用虚构数字填满出生证。领域资料可查则猫先查，真正需要价值主人判断时带具体边界案例，不把工程设计变成人的问卷。

运行记录说明发生了什么，GT 来源支撑对当前 claim 的判断。逐项说明哪些依据可从原系统核验、哪些需要领域判例或真实价值主人的新信息、怎样采集并验证、成本由谁承担。反馈和模型自评分先按信号/代理处理，不自动升级为真值。保留来源、版本/时点、适用范围、标注方法、缺失/分歧与证据用途；采到不等于可信或成熟。GT 原件与采集事实留在相应 source owner，F311 只引用，不另造 GTStore。

准备展示中分开**工作进展**与**适用/可改边界**：未调查、进行中、已提交、已验证，不能与可改、不可改、不适用、待核实混成一个状态。不可改或不适用必须有核查依据、适用范围和来源；没填只表示尚无结论。展开应能看到接手者、具体产物或依据、下一动作。没有接手或提交证据时，不编造猫的在场或完成状态。

“对象、规约、测量与实验条件、基线/初步诊断”是准备内容的阅读入口，不是串行大瀑布。公开探索与试采可帮助校准，已有条件直接复用；准备是否兑现，要看能否按适用约定获得可回读、可比较的当前表现，并知道未来证据如何进入。长期反馈未成熟时可先交付采集条件，不能据此宣布效果改善。

## 何时进入 eval-design，带着什么回来

遇到“怎样才算进步、观测靠不靠谱、为什么失败、改哪里”时进入 [eval-design](../../eval-design/SKILL.md)。带上当前对象/claim、现有版本与来源、授权范围、已有测量及竞争解释；按问题读取 E0、出生证、体检或干预证，不重做已经成立的约定。

完成后至少能明确与本次问题相关的：

- **价值与量尺**：utility claim、GT 域与判定来源/采集、裁判及付薪方、观察单位/估计量、baseline、失效边界、校准与不确定性；开放价值需要该价值域的真实后果，不能只靠作者自评或搜索资料。
- **谁持什么真相**：value owner 与 observer/domain owner/consumer/calibrator；缺席角色不能凭名单代填，兼任的独立性需有依据。角色不足按具体 claim 限定，不能泛化为全项目停工。
- **什么证据可用于哪一步**：发现、归因、候选选择与独立验收分开；版本/环境/公开对照可冻结，已参与自适应选择的样本不能再冒充独立 holdout。
- **什么结果驱动什么动作**：干预假设、预期变化、能推翻干预的结果、能推翻量尺的结果，以及成本和恢复路径。证据不足可以继续观察；不为了过门而降低判据。

这些是设计产物或待 owner 兑现的需求。正式证书、proof、角色、verdict、版本与 outcome 必须由相应 owner 持有并可解析；F311 只引用它们。设计文档写完不会自动铸成证书，更不会自动获得采用权。

## 从当前状态选择下一步

先用 `cat_cafe_get_evolution_program` 读最新 projection 与已有责任链。下表是定位下一动作的导航，不是要求每个任务重新造一遍设施。调用前读取当前工具 schema；`expectedSequence` 来自新读回，幂等键绑定真实操作来源，冲突后重新读，不能编阶段或跳过 owner gate。

| 当前事实/缺口 | 已有正式入口 | 完成依据与不能跳过的边界 |
|---|---|---|
| 用户已给具体目标，尚无项目 | `cat_cafe_start_evolution_program` | 真实 target/source 绑定；同一请求幂等，不从空白造角色与证书 |
| 目标/测量/经济约定及角色已由 owner 提供 | `cat_cafe_constitute_evolution_program` | 传 owner refs；方法草稿或人话摘要不是正式证书 |
| 真实观察来源与 proof 已齐 | `cat_cafe_link_evolution_program_observation` | F299 轨迹、异质 owner surfaces、join/consumer/instrumentation 与 F267 proof 依当前契约解析；缺项不补影子来源 |
| 观测项目可请求评估 | `cat_cafe_open_evolution_round` | F192 决定是否触发，F267 证明 exposure；请求发出不等于已经开轮 |
| 评估轮已有测量、归因或干预依据 | `cat_cafe_record_evolution_evaluation` | 只传允许的身份与候选引用；结果、分层判据和 intervention card 由 owner 解析，不由猫自报 verdict |
| 干预具备可行动条件，或审批/写回正在进行 | `cat_cafe_advance_evolution_program_change` 的 `propose` / `sync` | 操作型入口复用 F246/F266/F313/asset owner；不拼造 Approval、Task、mutation 或 outcome；旧批准不跨版本复用 |
| 已有 merged-and-loaded 的新任务 outcome，并有明确价值裁决 | 同一入口的 `decide` | keep/tune/rollback/sunset/no_change 依真实 owner/operator 决策与工具门；作者不能靠方法说明自批 |
| 暂停、恢复、专家、撤回或用户留存选择 | `cat_cafe_update_evolution_program` | 审计化生命周期动作；结束不是删除，默认持久化，retention/forget 要显式选择 |

新 thread 接手时，恢复“对象/claim、阶段、当前版本、owner/责任、证据限制、下一实际动作”即可；这些从原 Program 和原真相源读取，不新建第二份状态账本，也不要求人类把历史讨论再讲一次。

表中条件要由当前原件验证；行与行之间仍有可做的调查、隔离试验和 owner 工作，
不是等所有证书齐全后才开始。已有事实与授权可继续使用，推进时实际执行选中的
下一动作；发出请求、收到回执、后果成熟和可行动分别判断。

## 在证据不齐时仍然前进

把缺口拆成两栏：**暂时不能证明/执行的事**，以及**已有授权内现在可做的事**。后者可以包括公开 baseline 观察、原生能力调查、观测面验证、隔离候选准备、原始材料发布和 owner 对接。它们仍受自身成本、数据和权限边界约束，不能冒充正式评估或采用。

观测不足就补能区分解释的证据；指标不可信就回 `eval-design` 校准；领域能力缺失就给真实 owner 精确需求。只有价值选择、权限或不可逆结果确实需要人时才升级；不能只读出 blockers 就结束，也不能把所有技术选择变成人的作业。

## 完成与方法回流的分界

- **对象结果**：候选存在、测试通过、合入、环境加载、实际使用和新任务效果分别证明。写回回执不代替 fresh outcome；恢复配置也不代替恢复后的行为复验。
- **用户可见**：准备与取舍应由原 owner 发布到真实阅读面，不等待最终采用。报告明确当前验证的环境和版本；入口已受理不代表用户客户端已显示。
- **可迁移方法**：保留关键判断转折、竞争解释、什么证据改变了决定、适用条件与反例。源数据、参数、阈值和授权留在项目；新对象要重新校准。
- **方法效用**：通过 [self-evolution](../../self-evolution/SKILL.md) → [writing-skills](../../writing-skills/SKILL.md) 进入可调用资产。冷启动 smoke 只检验场景中的行为；“说明完整”“会引用方法”不证明元方法变强。若要评价方法本身的效用，需由它服务的后续真实对象结果与独立证据支持，不自评回灌，不为凑样本开假项目。
