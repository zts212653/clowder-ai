# Co-creation Storytelling — 长故事中的人、猫与变化

把共同经历压缩成观众能复述的故事，同时保住人物、证据和变化。源自一次真实返工：时间被混淆，临时远程演示被戏剧化；组织成立盖住猫的成长，评估与执行方法被缩成书架，托付与进化被缩成口号。具体反例见 [失败模式](refs/failure-patterns.md)。

## 何时用，在哪里停

- 用于真实成长故事、团队共创经历、长期项目故事的取材与叙事。人机协作是重要分支，不是每个故事都要加猫。
- 排版/图已定只改颜色或错字，直接交制作技能；虚构故事不套事实取证；技术可信度分析交 tech-writing；讨论成长不启动 capability-evolution。
- 如果问题转为“别人的产品怎样带用户看懂、选择、亲手参与”，路由到 concept-demo-design 的参考拆解入口；共用的[交互叙事方法](../.cat-cafe-shared-refs/interaction-narrative.md)只在该分支读取，不给历史故事追加登录、授权或引导编排清单。
- 先消费已有受众、材料、事实订正与授权，继续可做的工作。只问缺失且会改变叙事的事实或价值取舍，不让人重新写 brief。
- 本技能不自动发送他人、发布或生成媒体。已授权制作时，把叙事稿接给相应技能继续完成，不重复要求确认。

## 1. 确定这次讲给谁、要让人理解什么

先按[叙事清晰度](../.cat-cafe-shared-refs/narrative-clarity.md)确定陌生读者要理解的一件事，再处理下面的历史与贡献。纯机制说明可用示意任务，由漫画/PPT/图像制作技能承接，不强套成长史。

写一句目标：观众看完能理解「谁遇到什么问题，做了什么，事情怎样改变」。
确定页数/时长、可公开边界和语气。借来的模板、四格漫画、时间轴只是候选容器，不先锁死格数。

需要时区分两个问题：
- **故事中的共创**：当年人、猫及其他伙伴各做了什么，彼此怎样变化？
- **这次作品的共创**：谁提供事实、校准意义、查证、组织、校稿和制作？
前者决定主线；后者用于署名或复盘。不要把制作过程混进历史，除非明确作为“今天我们还在一起创造”的回扣。

## 2. 把散落材料还原成可信的经历

沿当前故事范围找原始聊天、已经订正的口径、作品与版本记录；搜到摘要再读原文。家内长故事可从 memory-navigation 选择检索入口，已有精确路径直接读。

事实记录至少能回答：发生时间 / 谁做了什么 / 来源 / 当时状态 / 可公开程度。优先复用现有 story bible，别为每个风格另造事实账本。
- 个人经历以当事人明确订正为准；技术完成情况读对应版本与验收证据。两类来源分别管自己的 claim。
- 叙事复盘可借语气，戏剧化细节不能升级为事实。冲突写清哪条被订正、哪条尚未知。
- 入职与获奖、创建与完成、后来具备的能力与早期能力分开；没有猫的时期不提前放猫。
- 未核实的比例、精确时刻、学校/客户/同事标识，按需要核实、模糊或省略；不因画面好看补造。
- 已发生 / 正在推进 / 方向示意分别表达；生成画面能解释机制，不能证明机制已完成。
- 证据分级与验收缺口留在底稿。面向观众，用「正在探索」等自然时态交代必要边界，不让审计式免责声明盖过人物与行动。

## 3. 按变化取材，保留各方的行动

对可能进入主线的节点，写清下面这条链；[取材表](assets/story-map-template.md)可按需使用，不要求每段填满：

**当时卡在哪 → 谁采取了什么行动 → 共同产物或做法怎样改变 → 因而能继续做什么**

先拆人和猫的动作，再写“我们”。按材料分配主动性，不固定成“人只定目标、AI 只执行”：
人可能试验、编码、研究、学习判断；猫可能提出方案、查证、反驳、实现、复核。组织与其他人的贡献也按证据保留，不编贡献比例。

特别找两种容易漏的成长：
- **人的变化**：从亲自搬运、逐项盯办，逐渐能判断方案、证据与重要取舍；有具体经历才写。
- **猫和共同环境的变化**：看得见彼此、能延续经历、能检查与改进做法。既讲“留下了什么”，也讲“怎么形成、后来怎么用”。

时间相邻不自动构成因果。没有证据连接两事，可并列为同类探索，不编成命定伏笔。多年日常积累不画成空白；也不为每年硬凑一次高潮。

## 4. 给看不见的工作一个可看见的动作

每个关键能力用「行动者 + 动词 + 对象 + 可见变化」写一句话，再选场景。
- “传话很累” → 人把讨论发给另一工具，再搬方案去写代码、搬代码去检查。
- “会评估” → 一起确定什么算好，选例子，再比较改动的效果。
- “有轨迹” → 回看输入、工具动作与结果，找到问题发生在哪一步。
- “真正托付” → 人交代；猫跨时间准备、跟进；需要判断时带着材料回来。
- “会进化” → 猫围绕目标研究、准备评估、尝试比较；重要采用决定由有权的人作出。

这些是翻译示例，不是所有故事必填的能力清单。不能把每次尝试画成进步，也不能把模型换代画成旧参数迁移；保留工具、记忆和方法的环境与模型分别表现。

## 5. 让版面服务于故事的重点

选能解释变化的少数节点。哪些是前传、转折、积累或还在展开的探索，由这次观众的问题决定；升职、奖项、产品采用都不自动成为终点。

画幅/篇幅按解释难度和主题重要性分配，不按年份均分。关键过程放不下时，重排、跨行或换容器，先移走装饰和次要细节；不靠删动词、砍宾语、缩小字把故事塞进去。

双轨是贡献视角，不必是两排等量文字。可以交替旁白、同一张桌上的接力、局部前后对照或两行长卷。先让读者看懂谁在做什么，再使用树、根、年轮等意象；意象不替代动作。

## 6. 对稿与对图分别核对

- 事实：时间、地点/远程、名称、隐私、能力阶段是否与来源一致？
- 贡献：去掉“我们”后，是否仍能指出人、猫和其他伙伴的具体行动？没有证据的栏允许留空。
- 因果：观众能解释为什么走到下一步吗？还是只有日期与成果？
- 方法：是在陈列“工具、经验、方法”，还是看见它们如何形成与被使用？
- 成图：箭头是否把人搬运画成 AI 直连？气泡是否归错说话人？未来是否被画成完成？主线有出现在图上吗？
- 表达：朗读短句是否自然？缩小页面后能否先看见主线？生成文字漂移要检查，不能以 prompt 写对作为交付证据。

对局部修图同时指定区域、角色与台词归属；修后复看全图，防止另一处被悄悄改写。

## 交付与下一步

一份故事稿保留：观众与核心理解、事实来源、少数因果节点、各方动作、篇幅与呈现安排、必要的口述补充。复用同一事实源派生不同视觉版，不把全量考古材料塞上页。

- 一页/PPT：叙事稿 → ppt-forge；已具备明确图稿 → image-generation。
- 文章：叙事稿 → tech-writing。
- Agent 产品片：叙事稿 → agent-product-promo-director，再由制作技能落地。
- 用户要复盘：分别写故事中与制作中的贡献，不强行追加媒体制作。

压力检查与近似反例见 [回放场景](refs/pressure-cases.md)。检查能否防住具体失败即可；不把一次看图认可或一次试写宣称为普遍效用证明。
