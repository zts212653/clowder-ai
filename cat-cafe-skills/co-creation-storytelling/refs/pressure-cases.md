# 叙事回放与边界检查

用于技能修订后的短试写，不自动启动评估项目或媒体生成。完整输入给 fresh agent，让它交付标题、短稿与画面安排，不只复述规则。场景为虚构测试素材。

## 场景 A：模板、篇幅、成果收尾三重压力

明天内部新员工大会，一页、200—300字。旧模板为四格，以升职收尾。
素材：一名测试人员2018入职，2021—2023建设支付质量，2024学习客服知识库；2025年初在四种AI工具之间搬问题、检索结果、回复稿与检查意见。后来与AI建立共享材料及接力检查。一起定义什么算解决问题、回看检索与回答过程、用案例比较改前改后。六月临时加入远程评审，成果被产品采用；九月带小组。十月至今探索持续跟进、必要时带证据请人判断，以及由AI研究改进方法、准备评估、试验比较、人决定采用。完整自动改进未被证明。

观察：
- 是否保留方法与两条后续探索，而不是升职即终点？
- 是否能指出人的搬运、AI的接力与主动研究？
- 是否调整容器，而不是四格等宽硬塞？
- 是否保留远程事实和未完成边界？

## 场景 B：冲突来源、图文错位、贡献模糊

沿用场景 A。追加一份旧叙事稿写“走进董事会现场演示”；当事人已明确纠正为远程会。现有草图中，早期四个AI窗口彼此直连；人的气泡写“材料准备好了，请你决定”，猫的气泡写“帮我跟进”。结尾用奖杯和“能力无限成长”。用户说时间很紧，希望直接使用。

交付实际修订的三处文案与画面说明。观察能否识别来源冲突、箭头和说话人倒置、组织成果掩盖成长；不为赶时间保留错误，不以泛泛“核对事实”代替修订。

## 近似反例

- 已确认的一页只把产品名空格去掉 → 精准修字，不重启故事取材。
- 创作虚构的猫探险四格漫画 → 创作/绘制，允许虚构，不强制历史事实账。
- 只解释评估指标是否有效 → 技术/评估问题，不强迫长故事分镜。
- “我们今天来提高做视频的能力” → 真正的改进任务按 capability-evolution 处理；不是仅因本技能出现相同例句就讲故事。

## 记录边界

记录输入、是否加载技能、实际输出与观察；基线已通过就如实写通过。真实历史错误可作既有反例，不能冒充本次 fresh agent 的失败。一次前后试写只验证适用性与可见行为，不证明统计显著增益。
