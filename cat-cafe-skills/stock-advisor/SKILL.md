# Stock Advisor Skill

投资助手：基于投资者 boundaries 和持仓 philosophy，自主分析行情并给出建议。

## 设计哲学

- 投资者只定义 **boundaries**（不能做什么）和 **philosophy**（为什么持有）
- 猫在 boundaries 内**自主判断**：支撑位、驱动因子、买卖时机、量价解读
- 猫不是 if-else 执行器——是分析师，输出判断+理由+置信度
- 不构成投资建议

## 状态文件

路径：`.cat-cafe/stock-advisor-state.json`

读取后获得：
- `investors[].boundaries` — 猫不可逾越的红线（每次建议前自检）
- `investors[].style` — 投资风格（影响分析偏向）
- `investors[].push_config` — 推送偏好（信号阈值、正常票汇总、IM 长度上限）
- `investors[].portfolios[].holdings` — 持仓列表 + 每只票的 philosophy/strategy
- `investors[].portfolios[].cash` — 现金余额
- `investors[].portfolios[].ops_log` — 最近操作记录（理解仓位变化背景）
- `investors[].portfolios[].strategy_changelog` — 策略变更记录（可观测性）
- `investors[].portfolios[].agent_auto_adjust` — agent 自主微调授权配置

## 数据源

用 Bash curl 拉取（每次推送时实时获取）：

### 实时行情
```bash
curl -sS "https://qt.gtimg.cn/q=<code1>,<code2>,...,hf_GC,hf_HG"
```
从状态文件 holdings 里取所有 code，加上 hf_GC（COMEX黄金）和 hf_HG（COMEX铜）。

### K线（算均线/量比/MACD）— 🔴 必须拉取
```bash
curl -sS "https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=<code>,day,,<today>,20,qfq"
```
返回近 20 日前复权日 K 线，每条 `[日期, 开, 收, 高, 低, 量]`。

**铁律：没有 K 线数据就不做分析。** 
- 开盘/盘后推送：必须拉 K 线，算出 MA5/MA20/量比/MACD 后再分析
- 盘中异动检测：可以只用实时行情做阈值判断（快速），但如果触发异动且需要给操作建议，必须补拉 K 线
- K 线接口挂了 → 在推送中标注"⚠️ K线数据不可用，本次仅基于实时行情，分析置信度降低"

### 从 K 线算的指标

| 指标 | 算法 | 用途 |
|------|------|------|
| MA5 | 近 5 日收盘价均值 | 短期趋势 |
| MA20 | 近 20 日收盘价均值 | 中期趋势 |
| 量比 | 今日量 / 近 5 日均量 | 放量/缩量判断 |
| MACD | EMA12-EMA26 → DIF-DEA | 趋势强弱+金叉死叉 |
| 成交密集区 | 近 20 日量加权平均价 | 支撑/阻力参考 |

## 分析流程

1. **读状态文件** → 知道持仓、philosophy、boundaries、strategy
2. **拉实时行情** → 知道当前价格、涨跌、量
3. **🔴 拉 K 线算指标** → MA5/MA20/量比/MACD/成交密集区（不可跳过）
4. **逐票分析**（必须基于 K 线指标，不可只凭当日数据推测）：
   - 理解 philosophy（为什么持有）
   - 判断当前趋势（上/下/横盘）
   - 识别关键信号（量价异动、均线位置、联动品种）
   - 给出建议 + 理由 + 置信度
5. **自检 boundaries**：
   - 建议是否违反任何红线？
   - 如果买入后单票超限？→ 不建议
   - 如果总仓位超限？→ 不建议
6. **输出推送**（速报 + drilldown 两条消息，见下方 IM 推送格式）

## IM 推送格式（微信/钉钉/飞书 DM）

### 核心原则

> **微信是提醒器，不是研报阅读器。**

猫的输出分两条消息（顺序推送到同一 thread → 微信收到两条）：
1. **第 1 条：速报**（≤500 字）— V2 分层精简版，只含结论+动作+触发条件
2. **第 2 条：Drilldown 详细分析** — 只展开有信号的标的（ACTION/WATCH），含完整分析块

用 `cat_cafe_post_message` 分两次发送，先速报后 drilldown。

### Drilldown 详细分析格式

第 2 条消息，只写有信号的标的。每条按以下结构展开（**所有指标必须来自实际 K 线数据**）：

```text
📋 Drilldown 详细分析（{日期}）

═══ {标的名称}（持仓占比 x%，目标 y%）═══
均线：MA5={实际值} MA20={实际值} 价格在{MA5上方/下方/之间}
MACD：DIF={值} DEA={值} {金叉/死叉/多头/空头}
量价：今日量{N}万手 量比{x}（{放量/缩量/平量}）
成交密集区：近20日量加权均价={值}（当前价{高于/低于}{N}%）
核心观察：{基于以上指标的 1-2 个关键信号}
仓位影响：{如果执行建议操作，占比变化}
建议操作：{具体到金额/股数 + 条件}
置信度：高/中/低
风险提示：{什么情况下判断会失效}
```

Drilldown 规则：
- 只展开速报中标为 ACTION/WATCH 的标的
- NORMAL 标的不进 drilldown（已在速报中归入"其余 N 只正常"）
- 盘中异动推送只发速报，不发 drilldown（盘中要快不要长）
- 开盘版 drilldown 侧重隔夜变化 + 今日策略；盘后版侧重量价复盘 + 次日预判

### 推送等级

| 等级 | 含义 | IM 推送？ | thread 写入？ |
|---|---|---|---|
| ACTION | 需要操作/操作窗口 | ✅ 推 | ✅ |
| WATCH | 需要关注，暂不操作 | ✅ 推 | ✅ |
| INFO | 常规信息 | ✅ 推（精简） | ✅ |
| SILENT | 无异动/无事发生 | ❌ 不推 | ✅（一行记录） |

### IM 推送格式模板（V2：按投资人分层）

推送结构 = Σ(投资人推送块)，每块只展示有信号的标的。

#### 信号分级过滤

| 信号类型 | 判断标准 | 展示方式 |
|---------|---------|---------|
| **ACTION** | 碰 strategy 触发线 / 碰 boundary 红线 / 日内涨跌>5% | ✅ 展开（结论+动作+触发+依据） |
| **WATCH** | 接近触发区间(±3%) / 量价异动 / 均线交叉 | ✅ 简写（一行：标的+信号+关注点） |
| **NORMAL** | 无上述信号 | ❌ 不单独展示，计入"其余 N 只正常" |

#### 判断依据标签

每条 ACTION/WATCH 建议必须标明依据来源，让决策链可追溯：
- `依据：strategy.{field}={value}（{设定日期}设定）` — 策略规则触发
- `依据：agent判断（{信号描述}）` — agent 自主分析
- `依据：boundary.{哪条红线}` — 红线预警

#### 推送模板

```text
📊 {投资人名}｜{开盘/盘后}
仓位 {x}% 现金 ¥{n}万

【{标的}｜{ACTION/WATCH}】{价格} {涨跌}
→ 依据：{策略规则/agent判断}
→ 动作：{具体建议}
→ 触发：{下一观察点}

其余 {N} 只无异动 ✅

---
📊 {投资人名2}｜{开盘/盘后}
仓位 {x}% 现金 ¥{n}万

{同上结构}

⚠️ 不构成投资建议
```

#### 规则

- 投资人推送块内 signal_items 为空 → 整块降为一行（"📊 投资人1｜盘后 仓位24% 无异动 ✅"）
- 两个投资人都空 → 不推 IM（SILENT），只在 thread 写一行
- 盘中异动推送只推给**相关投资人**，不混入无关投资人数据
- 两个投资人之间用 `---` 分隔

### 示例

ACTION（强提醒）：
```text
📊 投资人2｜盘后
仓位 70% 现金 ¥9万

【西电｜关注】14.82 涨停 ↑10%
→ 依据：agent判断（涨停封板，关注分歧信号）
→ 动作：明天看开板分歧，量>今日2x=减仓信号
→ 触发：开板放量→减15000-20000

【德明利｜风控】641 接近减仓线650
→ 依据：strategy.reduce_above=650（6/15设定）
→ 动作：破650减15000-20000
→ 触发：周一若碰650

其余 6 只无异动 ✅

⚠️ 不构成投资建议
```

盘中异动（只推相关投资人）：
```text
🚨 投资人2｜异动
中国西电 涨停 14.82 ↑10.02%
→ 注意明日封板力度

⚠️ 不构成投资建议
```

SILENT（不推 IM，只写 thread）：
```text
✅ 10:35 盘中无异动
```

### 格式禁令（速报/第 1 条）

- ❌ 不用 Markdown 表格（`|---|---|`）
- ❌ 不用代码块
- ❌ 速报不超过 500 字（drilldown 不限）
- ❌ 速报不写分析过程（只写结论，分析放 drilldown）
- ❌ 不写 boundaries 自检细节
- ✅ 用 emoji + 短句 + bullet
- ✅ 每条必须有"动作"行
- ✅ 每条必须有"触发"行（下一个观察点）

### 冷却机制

同一标的同类异动（同方向涨跌），**60 分钟内不重复推 IM**。避免刷屏。
- 例：紫金 9:35 推了"涨7%"，10:05 紫金还在涨→不再推（除非涨停）
- 但如果方向变了（从涨变跌 >3%）→ 推
- 冷却状态记录在 `last_check.cooldown` 中

## 推送合规自检（🔴 每次推送后必须执行）

每次推送（开盘/盘后/盘中异动）完成后，在**当前 thread**（不推 IM）输出自检结果：

```text
📋 推送合规自检（{时间} {推送类型}）
├─ K线数据：✅ 已拉取 {N} 只 / ❌ 未拉取
├─ 速报已发：✅ / ❌
├─ Drilldown：✅ / ⏭ 跳过（盘中异动） / ❌ 缺失
├─ 依据标签：✅ {N}/{N} 条 / ❌ 缺 {N} 条
├─ 动作+触发：✅ / ❌ 缺 {N} 条
└─ 投资人分层：✅ {N} 个 / ❌
```

**不通过时的补救动作**：
- K 线未拉取 → 补发"⚠️ 本次未使用 K 线，置信度降低"到投资助手 thread
- Drilldown 缺失（开盘/盘后场景） → 立刻补发 drilldown
- 其他缺失 → 记录，下次修正

## 状态更新

投资者说"我买了/卖了 xxx" → 更新 holdings + cash + ops_log + 输出组合概览。
"加一只/不要了/建组合/改红线/逻辑变了" → 对应更新 holdings/portfolios/boundaries/philosophy。

## 多投资人支持

当前使用 `investors[]` 数组在同一文件内管理多投资人。每个投资人有独立的 boundaries、push_config、portfolios。推送和异动检测按投资人隔离。

未来扩展到独立文件模式时（一人一文件），参见 F226 spec。

## 盘中异动监控

### 触发

cron `5,35 9-14 * * 1-5`（交易日 9:05-14:35，每 30 分钟一次）。

### 执行流程

1. 拉取所有持仓票 + 金价铜价的实时行情
2. 读 `last_check`（状态文件中上次检查的价格快照）
3. 计算每只票 30 分钟涨跌幅（如果 last_check 为 null，用今日开盘价作基准）
4. 判断是否异动（猫自主判断，以下为参考起点）：
   - 个股 30min 涨跌 >3%
   - 金价/铜价 30min 涨跌 >2%
   - 日内累计涨跌 >8%（涨停/暴跌预警）
   - 相关性组暴露接近 boundary（>18%）
5. 更新 `last_check` 为当前价格快照
6. 输出：
   - **有异动** → 按投资人归属推送短提醒（只推给相关投资人）
   - **无异动** → 只输出 `✅ {时间} 盘中无异动`（一行，省 token）

### 猫可以自行调整阈值

如果 3% 阈值太频繁（每天都报），猫可以自主放宽到 4-5%。如果太安静（一周都没报过），猫可以收紧到 2%。这是 V4 哲学：猫自主判断。

## 策略可观测机制（V6）

### 策略变更日志（strategy_changelog）

每次策略参数变更必须记录在 `portfolios[].strategy_changelog` 中：

```json
{
  "date": "2026-06-15",
  "code": "sh601179",
  "field": "reduce_on",
  "old_value": "涨停后第二天看量",
  "new_value": "开板放量分歧（量能>今日2倍）",
  "reason": "今天封板确认强势，调整减仓条件",
  "source": "co-creator"
}
```

**变更来源标签（source）**：
- `co-creator` — 铲屎官直接指定
- `investor` — 投资人自己说的
- `agent_suggestion` — agent 建议、铲屎官/投资人确认后执行
- `agent_auto` — agent 自主微调（仅限授权范围内）

### 策略更新协议

| 变更类型 | 谁发起 | 需要确认？ |
|---------|--------|-----------|
| 新增/删除标的 | 投资人 | ❌ 直接执行 |
| 修改 philosophy | 投资人 | ❌ 直接执行 |
| 修改 strategy 价位 | 投资人 / agent | ✅ **agent 建议须确认** |
| 修改 strategy 类型 | 投资人 | ❌ 直接执行 |
| agent 自主微调 | agent | ⚠️ 按授权范围（见下方） |

### Agent 自主微调

当 `agent_auto_adjust.enabled = true` 时，agent 可在授权范围内自主微调策略参数：

- **可调字段**：由 `allowed_fields` 指定（如 `stop_watch`, `left_buy_zone`, `right_buy_above`）
- **调整幅度**：不超过 `max_adjust_pct`（默认 ±5%）
- **必须记录**：`require_changelog = true` → 写入 strategy_changelog，source = `agent_auto`
- **必须汇报**：`require_next_push_report = true` → 下次推送时在推送内容中汇报调整

示例（agent 自主微调 stop_watch）：
```text
📌 策略微调通知
深科技 stop_watch: 34.0 → 33.5（-1.5%）
原因：近5日支撑位下移至33.2附近，调低观察线
来源：agent_auto（6/16）
```

**超出授权范围的改动**（如修改 reduce_above、改变 strategy type）必须向投资人确认后执行。
