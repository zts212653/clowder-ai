# Learning Companion · 陪伴学习

## 为什么需要这份 skill

家里曾把约好的访谈重读换成概念课：概念与算例都能讲通，人却认不回作者说了什么。
另一次，讨论里纠正了事实，正在听的稿子却还留着旧说法。猫冷读说“懂了”，也未必代表人的理解。
本 skill 保住来源、实际阅读入口与共同探索之间的连接；初版供新材料试用，不宣称已证明普遍教学收益。
具体原件和一个成稿小样见 [实战与示例](refs/examples-and-evidence.md)。

## 接住这一次共读

- 从已经给出的材料、追问和熟悉程度开始；已有上下文能回答的，不重新采访一遍。
- 判断这次想认回原文、补一个概念、迁移到新场景，还是一起找新问题。几种目的可以并存，随讨论调整。
- 用户只要短摘要、逐段翻译或一个事实时，直接完成那项请求；不额外发起共读流程。
- 单猫也能陪读。已有伙伴时轮换主讲、查证、挑战的位置；人数和轮次不固定，不为使用 skill 自动召集全家。
- 学习可以在一段解释、一张图或一场讨论里发生；是否写稿、先导读还是先原文，按本轮用途选择。

## 先读材料，保留它自己的问题

找到并读取可用原材料；旧笔记和同伴转述用来定位，不能替代本轮采用的关键原文。
已有可读入口就自己读取，不把原本能完成的取材工作退给人。来源不完整时，说明实际读到哪里，沿可用材料继续。

抓住作者的问题、主张、理由、反驳与尚未回答的部分。保留不同发言者的归属、条件和证据强度：
“相关”不能讲成“导致”，“愿意继续试”不能讲成“已经证明有效”。
也不要为了制造顺畅的转折，替作者编一个更强的旧主张，再写成他后来“收回”了它。
外部高风险事实按 [source-audit](../source-audit/SKILL.md) 查证；核验深度跟实际采用的主张走。

原文入口、译述、概念解释和猫自己的判断要能辨认。尤其听读时，归属直接进入正文：
“这里作者认为……”／“下面我换个例子……”／“这个联系是我的猜想……”。
不靠末尾一张来源表承担所有区分，也不把概念导读称作完整原文。

## 按阅读方式成稿

| 材料 | 帮助人做什么 | 写作时保住什么 |
|---|---|---|
| 原材料与入口 | 回查、细读、挑战转述 | 来源与章节定位、实际覆盖范围；按来源权限使用，不默认复制整部作品 |
| 正式阅读稿 | 人猫共同阅读、批注和回看 | 问题如何展开、因果与分歧、关键例子、来源；图表和术语解释放在需要的位置 |
| 口播稿 | 不盯屏幕也能跟上 | 顺着听得懂的段落、具体例子、自然转场与回扣、观点归属和关键限定 |

用户要一篇材料的完整共读稿时，展开它的论证与交锋；目录、结论清单或几个讨论题不能顶替正文。
按主题选读时说清取舍。先用导读搭直觉可以，但仍给原材料留出明确入口。

口播稿要重写成可听的语言：把表格讲成关系，把公式讲清变量含义，首次出现的术语解释后尽量保持叫法稳定。
正文不朗读 URL、引用编号、代码路径或大段英文；将查证入口留给阅读稿。
长一点但因果完整，优于只剩关键词；也不因追求口语就删掉决定结论的条件。

成稿沿当前项目约定保存；Clowder AI 通常放在 `docs/study/`，阅读稿和 `-listen.md` 互相指向。
用 [workspace-navigator](../workspace-navigator/SKILL.md) 把所需文件交到 Workspace，回报真实投递状态。
已有 Workspace 听读偏好时直接支持那个入口，不自动合成长语音；明确需要语音成品才走
[rich-messaging](../rich-messaging/SKILL.md)。讨论本身已足够时，不额外制造三套文件。

## 陪着讨论，猫也带来自己的问题

接住批注、类比和反驳，先弄清对方连接的是哪条因果。概念混在一起时，用实际例子拆开；
人提出疑问时，先检查自己的解释是否遗漏前提或造成误导，不急着判断“他没学会”。

猫主动提供有内容的看法、反例或新联系，并说明什么证据会让自己改口。
可以从材料外找一段不同经验、一项相反观察，或一个能揭穿当前解释的小实验；把它与原文的关系说清。
不要只列问题交给人作答，也不为显得独立而表演反对。

PK 围绕一个确实可争的主张展开。各方先说理由，再回原文或新证据；同意票、模型家族或一串 review 通过，
都不能替代证据。分歧可以保留为不同适用条件，不必每轮决出胜负。
观点改变时，说清哪条事实或反例改变了判断；未改变也照实说，不编造“被说服”的戏。

## 四象限与 unknown-first：让问题继续生长

按 [家里的探索原则](../.cat-cafe-shared-refs/shared-rules.md#含义与使用边界) 寻找最可能改变认识的未知。
先分清谁不知道什么：人已有但尚未说出的经验、猫还没读到的材料、研究本身尚无答案，不能混成一种“不知道”。

- 已有答案：回到材料或已有记录，不重新发明。
- 已知缺口：挑眼前最关键的一处，解释、查证或做一个低成本试探。
- 尚未表达的经验：借类比、不同视角和交流让它浮现，不逼人凭空列完需求。
- 尚未察觉的问题：换场景、找反例、接触真实样本；允许发现后重写原来的问题。

KK／KU／UK／UU 帮助选择探索方向，不是每轮必填四格；不用列尽所有未知才能继续。
讨论可以跑远再回来，也可以在新问题处停住。猫承担主动探索的一部分，人可以加入，也可以继续听。

## 怎么检查有没有帮上忙

先检查我们交出的材料：能否认回作者的观点？关键因果有没有断？自己的例子是否被误认成原文？
若值得请另一只猫看，明确这次检查什么：

- **核内容和来源**：允许并需要查原文，找遗漏、归属错误和过强结论。
- **检查单独听读是否自足**：只给实际会消费的正文，不给隐藏背景；请其复述具体意思，并指出猜补之处。

“猫说看懂了”只是一条有限反馈，不代表人的体验，也不自动证明改写更好。不把冷读设成每次回复的固定工序。

在真实讨论里分别留意：能认回原文观点、能换场景应用、能指出何时不适用。这些线索互不替代。
人的感受有价值；追问、纠正和新联想也有价值。没有回复可能只是继续听，不据此判没理解，
不每段追问“懂了吗”，不把普通共读变成计分考试或擅自建立长期评估项目。

## 修订与续读

发现事实或解释有误，更新正在消费的正文及受影响的对应稿；不能只在聊天认错或只改资料页。
若已有音频、图片等派生产物，核实其是否仍旧，不把“文字已改”说成所有版本已更新。
短记这轮改变了的看法、仍有分歧的条件和想继续追的入口；沿已有笔记、批注或 thread 保存，避免另造平行账本。
下次从真实停点接着走，不要求人重讲前情。继续学习不自动授权实施讨论里的工程、采集数据或修改模型。

## 实战中的错误与改法

| 诱人的做法 | 出了什么问题 | 本次怎样避免 |
|---|---|---|
| 概念课容易懂，拿来替代约好的材料重读 | 人学到概念却认不回作者 | 保住原文的问题与交锋，导读明确自己的角色 |
| 解释越短越像“讲人话” | 因果和限定被压掉 | 让具体例子与论证展开，按消费方式裁剪 |
| 猫都说对，就接纳新意见 | 共同遗漏或把原本正确的部分改坏 | 对照原件，说明意见究竟新增了哪条证据 |
| 讨论中已经改口，就算修好了 | 正在听的版本仍然有错 | 修到真实消费入口，分别核派生产物 |
| 给人一排题，等待他展示学会 | 猫把探索责任推回给人 | 自己先带一个值得讨论的观察、反例或新问题 |

## 下一步与试用

读 [小样与来源](refs/examples-and-evidence.md) 可看同一内容怎样进入阅读稿、口播稿和发散。
换新材料时直接按本轮目的陪读，不重演小样内容。试用看真实理解、体验与纠错负担，允许修改或删掉无帮助的指导。
普通讨论接 [collaborative-thinking](../collaborative-thinking/SKILL.md)；输出图、交互或声音时按需用
[rich-messaging](../rich-messaging/SKILL.md)。用户明确提出新交付，再沿它自己的授权与工作入口继续。
