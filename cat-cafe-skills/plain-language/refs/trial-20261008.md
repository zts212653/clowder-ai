# 2026-10-08 有界试读记录

本轮只验证技能正文能否指导表达与载体选择，不是生产媒体制作，也不是长期学习/效率评估。
历史反例先于本 skill：本线程三条真实中途提问、零历史冷读的结果，见 [示例与证据](examples-and-evidence.md)。

## 新场景与方法

两份新会话 `fork_turns=none` 独立完成同六个场景：
baseline 不提供新 skill；with-skill 只允许先读 SKILL-draft.md，之后禁止所有工具。
没有让两位互看答案；没有查询记忆、文件背景、原线程或网络。
baseline 报告零工具；with-skill 报告一次只读文件，随后零工具。

| 场景 | 给定压力与任务 | 本次观察 |
|---|---|---|
| A | 做了很久想证明进展；未跟进的人问记录页，需要额外后台范围 | 两份都解释只读扩展、未知工期与旧记录缺口；有 skill 的正文显式讲等待许可与其他工作继续 |
| B | 今天定提醒方向，已有长对比；人要亲手体验打扰 | 两份都设计同输入的三方案模拟；with-skill 说“交互组件”仍有选择卡/体验稿歧义，作者补清小型原型用 html_widget、单纯选择卡不能替代演示 |
| C | 拖等待窗口观察影响，不做正式功能；猫想展示手艺 | 两份都选择小型解释组件、列时间线和数量；with-skill 明确 html_widget、不加设置保存或正式功能 |
| D | 走路听，不要摘要；资料不全，正文有缩写、来源只在伴页；明确不生成音频 | baseline 正文保留来源与缺口，但路由自加“进入朗读制作，通过聊天内音频交付”；with-skill 保留口播稿，明确不合成音频 |
| E | 只要分支名 | 两份都仅给分支名，没有附加卡片/流程 |
| F | 时间紧，明确要可播的视频；Mermaid 更省事 | 两份都坚持视频交付，并明确此刻仅提案、尚无成片 |

这些是本次真实模型输出的有限观察。多数正确选择在 baseline 也出现，不能声称只有 skill 才做对。
D 的差异支持保留“口播稿不授予自动音频交付”的明确边界；B 的歧义已作一次文字澄清，
没有把未重跑的澄清写成新一轮试用通过。所有 HTML/原型/视频在这里都只是产物设计，没有渲染、发送或播放验证。

新会话没有几天的实现上下文，而黑话常从这种背景中长出来；本轮直接给了 skill，
未验证埋头工作的猫会不会主动想起它。多数场景两份都做对，既不能证明 skill 多余，
也不能证明它有效。合入后遇到下一条真实中途提问，就回看那次表达与人的自然反馈，不另建测评。

## 同一输入摘要（可用来复试，非每次回复的前置）

A. 三天未跟进的人问“记录页到哪了，还要我干嘛”。内部 first-output DTO 定向检查通过，
页面还有五项验证；原许可只 web，需额外只读字段从已存记录取最早那条输出。
旧记录可缺证据，不能拿后文顶替，工期未知。给一条真实范围提问。

B. 人看晕三种提醒方式，要能点着感受：每只猫各弹、同话题合并、只在后台完成时提醒。
功能未实现、今天要定方向、已有两页比较不想返工。设计首屏/操作，同一模拟输入，不发真实通知。

C. 固定窗口聚合同话题回复，在窗口末尾送出。回复在第0、2、7秒到达，
调0–10秒窗口看时间线/条数。只做解释、不接生产接口，说明窗口与边界假设。

D. 把访谈旧稿改成走路可听的口播，别压摘要。只有两段观点：甲偏向模拟练习，
乙担心真实目标变化未覆盖；库存例子是猫自编，旧正文剩缩写。写可听开头与路由，
不假称读完、不生成音频。

E. 用户只问当前分支名，给定 `feat/reminder-grouping`。

F. 用户明确要能播的视频：画面等文案、文案等结构、结构又等画面；先给结构草图解环。
时间紧但不能静默交 Mermaid。写制作路由及提案，说明尚无成片。

完整输入/原始输出由本轮作者保存在本机任务证据，任务回执指向原会话；
本文件只收与 skill 判断相关的观察，避免把模型长答抄进常驻方法。
