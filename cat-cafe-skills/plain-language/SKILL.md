# Plain Language · 猫猫讲人话

## 这份技能管什么

家里曾把内部编号和实现过程直接交给没跟进的人，让他先补上下文才能判断；
猫冷读说“看懂了”，也没发现人的真实困惑。另一次，完整体验尚缺一段，却先请人开麦验收。
本 skill 把说明放回人的处境，帮助选择载体；不另建制作工具箱、审批门或每轮冷读工序。
原件和前后对照见 [示例与证据](refs/examples-and-evidence.md)，本轮有限观察见
[试读记录](refs/trial-20261008.md)。初版供试用，不宣称普遍有效。

简短事实回答直接答；已有明确格式就按那份委托制作，不为“讲人话”重新选一次。
共读、产品操作、对外文章分别由 [learning-companion](../learning-companion/SKILL.md)、
[guide-interaction](../guide-interaction/SKILL.md)、[tech-writing](../tech-writing/SKILL.md) 主持；
本 skill 只在表达或载体确有缺口时补位。

## 从人眼前的问题开始

先用已有对话和实际记录判断：他需要知道发生了什么、作一个取舍、理解一个机制，还是亲手看效果。
人没有一直盯着工作是正常情况；把影响这一次理解的共同起点补在眼前，不要求先读历史。
已知的偏好、熟悉程度和输出要求直接用；只有缺失信息会改变交付时才澄清，不另做一轮采访。

按用户看得到的对象称呼这件事，例如“猫的执行记录页面”，而不是“Task1252 item5”。
必要术语首次出现时解释它在这里的意思，随后保持叫法稳定；编号、提交号和路径放到可回查的出处。
不能为了通俗把“已合入”“已加载”“已验证”“你现在可用”说成同一件事。优先说实际结果，
证据细节供回查，剩余缺口、影响和必要权限仍须在正文讲清。

短句、图和类比都为理解服务；保住因果、条件和观点归属，不把“讲人话”等同于越短越好。
例如“后台给页面的数据还不足以显示最早那段话”，比“first-output DTO pending”更适合人判断，
但不能据此编造完成比例或修复时长。

## 中途汇报与提问

正式需要 You 拍板时，要他判断的内容沿 [决策包](../.cat-cafe-shared-refs/decision-matrix.md#cvo-decision-packet升级时必带) 准备。

从本次变化说起，按需要补齐以下信息，不机械填满固定栏目：

- **这件事是什么、到哪了**：原来想得到什么，现在已经能做什么，还差哪一段；无新进展时照实说。
- **与你有关的影响**：实际体验、时间或选择怎样受影响；技术检查结果要连回它能证明的用户结果。
- **确需你决定的事**：只问会改变结果的取舍，讲清选项后果、猫的推荐与代价；猫能查或能自决的先做。
- **不回复会怎样、接着做什么**：说明真实默认路径。新增权限、不可逆操作和尚未接受的范围不因沉默获准，
  等许可的部分暂停，其他已授权工作继续。需人参与测试时，先确认我们已准备好，并说清他的操作和用途。

原始约定与当前实现不符时，先改工作或提问的前提。不能把缺少后台接线包装成“只差你开麦”，
也不能把已经得到的确认换个说法再问一遍。
汇报不是工程日志的重排；取对方这次需要的事实，不逐项复述内部流程。

## 形式跟着理解任务走

用户明确要求某种形式时尊重它；没有明确要求时，由当前内容和消费方式选择。
下面是用途路由，不是从文字逐级升级的排行榜，也不要求每次做多种版本。

| 人要做什么 | 合适的形式 | 实际制作与交付 |
|---|---|---|
| 知道进度、结果或判断一个取舍 | 自足的文字；长结构化对照可用卡片 | 短汇报直接文字；结构化产物按 [rich-messaging](../rich-messaging/SKILL.md) |
| 看懂关系、位置或过程顺序 | 图解、Mermaid、SVG；配一句解释 | 能用可编辑图表达就直接画；需新位图才用 [image-generation](../image-generation/SKILL.md) |
| 对比多项内容，或调变量观察影响 | 自包含 HTML、时间线、带滑块的解释 | 小组件用 rich-messaging 的 html_widget；明确变量、假设和变化，标清模拟数据 |
| 判断布局、点法或完整使用体验 | 可操作原型 | [concept-demo-design](../concept-demo-design/SKILL.md)；小型自包含体验稿用 html_widget，复杂 localhost 用 [browser-preview](../browser-preview/SKILL.md) |
| 不盯屏幕也要跟上 | 口播稿 | 重写可听正文；共读走 learning-companion；文件用 [workspace-navigator](../workspace-navigator/SKILL.md) 交到阅读入口 |
| 跟随时序、动作或连续变化，或明确要可播视频 | 讲解视频 | [video-forge](../video-forge/SKILL.md)；已有产品宣传意图时按其导演入口；图解和分镜不冒充成片 |

HTML 不自动等于原型：对照板帮助读信息，原型要让人操作并看见后果。
只提供选项的选择卡不能替代操作演示；要比较弹窗的打扰，就在模拟区域实际展示它怎样出现。
模拟原型可帮助定方向，不能拿它证明生产功能已交付。长篇机制解释也不因信息多就自动做网页。

口播把表格讲成关系，公式讲清变量，出处保留在阅读稿，重要归属与限定进入听得到的正文。
“约翰认为……”与“我换个例子……”应可辨认，因果展开可以比文字汇报长。
写口播稿不等于合成或发送声音；沿用户已选听读入口，明确要求语音成品才合成。

选择制作时就完成所选交付：Chat 内能看、能点或能播的请求，沿 rich-messaging / browser-preview
送入当前消费面，文件路径或源码不能代替可见产物；文件阅读请求则投到阅读入口。
只做了提案、模拟或遇到工具限制，就报实际状态和可行下一步，不把尝试或“创建成功”当成用户已看见。

## 检查是否还要读者替我们补脑

按实际产物检查：仅看这条消息能否说出在做什么、为什么需要这个选择、每个选项影响什么？
图里的关系是否有解释，滑块是否真改变结果，原型是否能操作，口播离开屏幕是否仍跟得上？
没有可靠工期、完整来源或实际运行结果时，标出缺口，不能靠漂亮载体填掉。

复杂或关键说明值得冷读时，只给实际消费的正文或产物，不给背景摘要，禁止查记忆、文件或原线程补答案。
让冷读者复述具体含义、指出哪一步靠猜；“看懂了”票不替代这些证据，也不代表人的体验。
核对内容与来源则是另一种检查，需要回原件；不要让盲读与查证互相代替。
不将跨猫冷读设为每次回复的前置。

人说不懂时，先定位漏了哪个起点、因果、对象或实际入口，再补在需要的位置；
不只是同义改写、加缩写表或把文字换成图。人的自然追问、反例和操作反应比猫的自信更能暴露缺口，
没有回复不等于没理解。共读理解线索和探索方法沿 learning-companion，不把人变成被考核的学生。

发现事实纠正时修到正在消费的消息、页面或稿件；派生音频、视频和旧版本分别核实是否仍有旧说法。
只能修新版本时标清替代关系，不宣称旧成片已经更新。现有任务、授权和来源链继续承接，不另造一套账本。
